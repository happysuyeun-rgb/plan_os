# PlanOS 실행계획 기반 개발 운영규칙 v1.0

작성: 2026-10-21 · 상태: **즉시 적용하는 업무 운영 기준**  
상위 기준: [통합 실행계획서](PLANOS_INTEGRATED_EXECUTION_PLAN_2026-10-21.md)

## 매 작업의 필수 순환
1. **계획서 먼저 확인:** 작업을 시작하기 전 GitHub `main`의 통합 실행계획서를 읽고 현재 게이트, 다음 우선 작업, 선행조건, 누락/불일치 목록 확인.
2. **한 개의 검증 가능한 기능 단위 선택:** 해당 작업의 목적·변경 파일·수용 기준·테스트와 되돌리기/운영 위험을 계획서에 기재. 반드시 기존 문서와 코드의 실제 상태를 비교.
3. **개발:** 별도 작업 브랜치/PR에서 기능 구현. 데이터 보호 P0에 영향 있는 변경은 운영 DB·배포·비용을 유발하는 외부 API와 분리.
4. **검수:** 정적 테스트뿐 아니라 가능할 때 빌드, 회귀, 권한, 오류·실패·경계값 테스트. 검사 누락·불일치·충돌을 기록하고 수정 뒤 재검수.
5. **완료 처리:** `[x]`는 **명시한 범위의 증빙(파일/커밋, 실제 CI run/테스트 결과)**이 있을 때만. 단순 코드 작성과 기능 전체 완료는 별개. `[ ]` 미실행·실패·불확실, `[!]` P0 차단은 텍스트로 표시.
6. **기록:** 통합 실행계획서의 `진행상태/완료 항목/불일치 및 결함/증빙/다음 작업` 5개 항목을 갱신. 노션 업무일지에도 완료·잔여·차단을 동기화(연결 가능한 경우).
7. **다음 작업 확인:** 최신 계획서를 다시 읽어 P0 선행조건과 빠진 기능, 다음 한 단위의 수용 기준을 확인하고 순서대로 진행.

## 진행 상태 정의
- **계획:** 요구사항·범위만 정의.
- **구현 중:** 작성·PR 단계, 미검증 가능.
- **검수 중:** 코드는 있으나 필수 테스트 중 일부 미완료.
- **완료:** 정의한 수용 기준과 테스트를 만족하고 관련 코드/문서의 상태가 일치. `main` 반영 여부 별도 명시.
- **보류/P0:** 안전 조건 미충족. 완료 체크 불가.

## 수행 우선순위
**두 작업 레인을 구분한다.** 기존 저장 데이터 유실/권한 이슈는 G1-P0 레인에서 해결하되, DB를 변경하지 않는 신규 AI 인력사무소 기능은 병행 개발한다. 문서·SQL 설계 단계만 반복하며 기능 개발을 무기한 지연시키지 않는다.

| 레인 | 현재 다음 단위 | 완료 기준 |
|---|---|---|
| 기능 레인 | AI 전문가 선택·업무 요청·승인 전 Mock 플로우의 범위 결정 및 실제 화면 개발 | 화면 흐름, 상태 및 실패 처리, 빌드·테스트, PR 증빙 |
| P0 안정화 레인 | 기존 문서 저장/복구의 CAS 경합, 직접 쓰기 우회 및 PR #15/#19 정합성 | 관련 DB/브라우저 테스트 PASS 전 운영 DB·main 반영 금지 |

## 금지
- 별도 승인 없는 운영 Supabase DB 마이그레이션·운영 배포·유료 AI 실행.
- Draft PR 생성/정적 계약 테스트만으로 기능 완료 선언.
- 기존 `[ ]`을 근거 없이 `[x]`로 변경하거나 과거 시점의 확인 내용을 현재 사실로 보고.
- 중복 파일/이전 상태 문서를 근거 없이 현재 구현보다 우선시.
