## 기존 기획 플로우 보존 대상
1. 비로그인 체험: 랜딩 인터뷰/결과 미리보기 → 로그인 → guest 세션 결과 이전. 
2. 프로젝트 생성: 단계형 기본 입력 → AI 인터뷰 질문/답변 → 산출물 생성 파이프라인.
3. 원래 문서 5종: PRD `prd`, UI '기능명세서' `ia`, 내부 화면목록 `screen_list`, 정책서 `policy`, Cursor 프롬프트 `cursor-prompt`. `screen_list`는 탭 숨김, 파이프라인/ZIP에는 포함.
4. 문서 작업 공간: 상단 산출물 탭, 좌측 항상 표시 AI 채팅(편집 가능한 제목·첨부), 중앙 편집/리뷰/버전, 우측 댓글 패널.
5. 사용자 수정: 직접 편집/자동저장, AI 채팅 통한 수정, 특정 문서/연쇄 재생성, 명시적 버전/복원/히스토리.
6. 반출: 현재 문서 MD, 전체 5종 ZIP, Cursor 프롬프트 복사. 추가 포맷은 전부 현행 제공 완료로 간주하지 않음.

## 개발 우선순위 영향
- 새 Mock S3→S6 플로우만 구현해서 'PlanOS 통합'으로 완료 표시하지 말 것. 실제 기존 기획 인터뷰/산출물/채팅 사용자 여정이 검수 화면으로 이어져야 함.
- 기존 기능 보존 자체를 신규 AI 실행 MVP의 착수 차단으로 확대하지 말 것: Mock 수직 기능은 분리 브랜치에서 병행 가능하되 운영 데이터 쓰기·AI 호출은 차단.
- 우선 기존 기능을 **재구현하지 말고 실제 src/** 코드 존재와 동작을 확인한 다음 빠진 기능만 보완.
- 제안 F-ID는 새로운 기능 확정이 아니며 현행 F-ID와 충돌을 재검사한 후 소유자 승인 없이 범위를 확대하지 않는다.

## 개발자(Cursor) 재검수 요청
1. `ProjectCreatePage`, `DocumentPage`, chat / generation / export 관련 소스 전체 호출자 매핑.
2. 각 5종 문서 타입의 실제 생성, 탭 표시, hidden screen_list 유지, ZIP 산출물 현황.
3. 인터뷰 답변 및 생성 진행 상태의 저장/재시도/실패 복구와 실제 AI 호출 여부.
4. 기존 문서 재생성·채팅 수정 후 승인/스냅샷 무효화 시나리오.
5. 기존 C09/C10 딥링크, 댓글/버전/내보내기/게스트 이전 브라우저 E2E.
