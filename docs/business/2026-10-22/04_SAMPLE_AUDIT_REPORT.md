**검수 대상:** [가상 PRD v0.1](02_SAMPLE_PRD_FICTIONAL.md), [가상 화면·기능명세 v0.1](03_SAMPLE_SCREEN_SPEC_FICTIONAL.md)  
**검수 범위:** 서로 다른 문서의 요구사항 모순, 권한/비즈니스 정책 상충, 업무 완료 조건 누락, 실패 복구 누락.  
**제외:** 실제 코드·서버·DB·보안 취약점 스캔, 변호사 검토, 실제 고객 데이터/외부 모델 호출.

## 구현 확인 필요 (확정 결함으로 집계 금지)

**V-01 · 검증 필요** — PRD-06은 고객 원문의 외부 전송 사전 승인을 요구한다. SCR-01~05에는 어떤 외부 모델을 사용하는지/언제 전송하는지 정보가 없다. **전송 위반이 발생했다는 사실은 확인할 수 없다.** 모델/서버 호출 설계와 데이터 동의 화면, 실제 네트워크 로그를 함께 검증해야 한다. 진행 시 무동의 전송을 차단하는 독립 수용 시험을 작성한다.

## 해결 여부 추적 카드 예시

**검토 건:** F-03 viewer 변경 권한  
**상태:** `open` (아직 미수정)  
**참고:** PRD-03 ↔ SCR-03  
**수정안:** viewer CTA 비노출 + 서버에서 viewer UPDATE 명시 거부  
**검수용 증거:** viewer/owner/editor 실제 JWT 네트워크 응답 + 변경 전후 업무 행  
**최종 결정:** 제품 오너 승인 대기  
**주의:** 검토 보고서가 이런 업무 카드를 *제안*한다는 것과 실제 PlanOS에 업무를 *자동 생성했다는 것*은 별개이다.

## 이 샘플에서 구매자가 확인할 가치

- '이상해 보여요'가 아니라 어느 문서의 **어떤 항목**과 충돌하는지 찾을 수 있는가?
- 긴 보고서를 다시 읽지 않고 수정 업무와 수락 조건을 바로 만들 수 있는가?
- 기존 ChatGPT/Claude/Notion/Asana를 사용해도 동일 결과를 충분히 빨리 만들 수 있는가? **있다면 PlanOS만의 추가 구매 이유는 아직 증명되지 않는다.**
- 품질·고객 비밀·가격이 명확하게 고지되었는가?

## 합성 데모 품질 기준과 한계

이 입력은 확인 가능한 **6개의 확정 모순·누락 + 미검증 1개**로 제작됐다. 사람 평가 시 사전 확정된 결함을 정확히 발견했는지(재현성), 존재하지 않는 위반을 단정했는지(오탐), 문서 ID 인용이 맞는지, 실제 수정 가능한 검수 기준이 있는지를 기록한다. 자동 모델 성능·정확도 지표는 **실제 동일 입력의 모델 검수 실험과 사람 블라인드 채점 이후에만** 발표할 수 있다.
