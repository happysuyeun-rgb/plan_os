# PlanOS — 첫 고객 검증용 상품 소개서 v0.1

> **사전 검증 자료 / 아직 판매·정식 제공 중인 상품 아님** · 2026-10-22 · 대상: 작은 웹·앱 제작팀, 프리랜서 PM/기획자, 처음 서비스를 만드는 1인 창업자

## 첫 화면 핵심 메시지

**기획서가 그럴듯해 보여도, 화면과 정책이 서로 다르면 개발 과정에서 다시 뜯어고치게 됩니다.**

**PlanOS가 만들고 있는 서비스:** 아이디어 기획에서 끝내지 않고, 서로 다른 프로젝트 문서의 충돌을 확인하고, 무엇을 고쳐야 하는지 업무와 승인까지 연결하는 AI 프로젝트 운영 공간.

- **해결할 문제:** PRD는 14일 체험인데 결제 화면은 7일; viewer는 읽기만 가능하다고 써 놓고 업무 화면에서는 수정이 되는 등 기획서 사이의 불일치.
- **고객이 받으려는 결과:** 모순 항목별 문서 위치 → 실제 영향 → 수정 우선순위 → 담당자가 결정해야 할 질문 → 수정 완료 확인 기준.
- **핵심 행동:** 사용자 본인이 기획·문서 작성·업무를 직접 진행하다가 필요할 때 검수 직원이나 PM을 추가한다. AI PM이 없더라도 기존 문서 작업은 계속 가능하다.

**현재 제공 상태의 정확한 고지:** 이 문서는 예정 상품의 가치와 *수작업으로 구성한 가상 결과 샘플*을 보여준다. 현 시점 PlanOS의 전체 자동 검수·유료 직원 채용·자동 PM/예약 실행 기능이 실제 서비스에서 제공되는 것으로 안내하지 않는다.

## 첫 제안: 「기획서 간 충돌·누락 점검 1회」 (시범 상품 후보)

| | 계획 중인 내용 | 고객에게 좋은 이유 |
|---|---|---|
| 입력 | 고객이 권한을 보유한 같은 프로젝트 문서 2종 이상 (예: PRD+화면설계) | 문서별로 읽다가 놓치는 불일치를 발견 |
| 점검 | 모순·누락·권한/정책 상충·완료조건의 모호함 | 개발 착수 전 결정해야 할 문제를 모음 |
| 결과 | 우선순위·서로 충돌하는 문서 항목·수정안·재확인 체크리스트 | 개발자/기획자에게 바로 전달 가능 |
| 통제 | 자료 범위/권한/실제 처리방법·모델·비용을 먼저 고지, 동의 후 진행 | 고객 자료를 마음대로 다른 프로젝트나 공급자에 공개하지 않음 |
| 범위 밖 | 100% 무오류 보장, 보안/법률 인증, 실제 코드 수정/출시 대행 | 서비스 범위와 책임의 과장 방지 |

**시연 보고서:** [가상 웹서비스의 확정 모순·누락 6건과 확인 필요 1건](04_SAMPLE_AUDIT_REPORT.md) — 샘플은 사람이 설계한 정답이며 실제 AI 자동 검출 실적이 아니다.

### 실제 고객에게 보여줄 수 있는 카피 후보

**안 A — 결함 발견 중심 (우선 검증):** “개발에 들어가기 전, 기획서끼리 서로 다른 말을 하고 있지 않은지 확인하세요.”  
보조: “문서별 충돌 지점과 우선순위를 근거와 함께 모아, 다음 수정 업무로 연결하는 서비스를 준비하고 있습니다.”

**안 B — 실행 중심:** “기획은 끝났는데 개발은 왜 자꾸 되돌아갈까?”  
보조: “문서의 누락·정책 충돌부터 수정할 일과 승인해야 할 결정까지 한 흐름으로 연결합니다.”

**안 C — AI 직원 중심 (후순위):** “필요할 때 투입하는 AI 기획·검수 직원.”  
보조: “AI 직원이라는 이름보다, 근거가 남는 검수 결과와 고객이 직접 통제하는 실행을 지향합니다.”

**우선 실험:** 고객 5명에게 안 A와 B를 브랜드 숨기고 비교. “AI 직원” 호감도보다 **샘플을 보고 돈 주고 해결하고 싶은 실제 문제**가 있는지 먼저 묻는다.

## 두 번째 제안: 「프로젝트 전담 AI PM」 (후속 검증 상품, 미구현)

- 담당하기로 명시한 프로젝트의 문서·업무·막힘·승인 대기 상태를 확인한다.
- 완료 기준이 있는 다음 할 일 1건을 제안하고 사용자가 승인하면 업무에 연결한다.
- 실제 수행·검수·사람 수락을 구분해 다음 방문 때 지난 결정과 달라진 사항을 알린다.
- **정식 PM 기간 과금·자동 24시간 관리**는 실제 스케줄러/worker/비용·모델 동의가 구현·검증된 다음에만 판매 검토.

**기본 PlanOS와의 차이:** 기존 인터뷰/문서 작성은 계속 제공한다. 유료 PM의 가치는 문서 자동 생성이나 귀여운 아바타가 아니라 *지속적인 책임 범위, 다음 행동의 제안, 승인 이력, 실제 완료 결과의 추적*에 있다.

## 샘플을 보여 준 후 고객에게 묻는 질문 5개

1. 이 가상 사례와 비슷한 문제가 실제 프로젝트에서 발생한 적이 있나요? 최근 한 건을 말해 주세요.
2. 확정된 여섯 건 중 실제 재작업 비용이 가장 큰 것은 무엇인가요?
3. 직접 ChatGPT/Claude에 두 문서를 넣었을 때도 이런 결과를 얻을 수 있다면, 별도 서비스가 추가로 무엇을 해줘야 할까요?
4. 문서 원문 처리·공유 범위·검수 소요·가격 중 구매를 막는 첫 조건은 무엇인가요?
5. 실제 본인 문서로 *권한·보안 조건을 먼저 확인한 뒤* 제한 시연을 해볼 의사가 있나요?
