## 1. 서비스 정의와 가치제안

**서비스 정의:** PlanOS는 개인·소규모 팀이 기존 AI와 함께 아이디어를 기획하고, **직무·업무 스타일·검증 경력·사용 AI 모델이 다른 AI 직원**을 고용해 프로젝트를 이어가며, 업무의 실제 실행 상태와 결과를 확인할 수 있는 프로젝트 운영 플랫폼이다. 채용된 AI 직원은 실제로 사람이 고용된 법적 관계가 아니라 권한·기간·예산 범위가 정해진 소프트웨어 실행 서비스다.

**고객에게 제공하려는 세 가지 가치**
1. **기획을 처음부터 끝까지 끊김 없이:** 아이디어/인터뷰/산출물/채팅을 유지한 채 업무·프로젝트 운영으로 이어진다.
2. **나와 일하는 방식이 맞는 전문가:** 공감형 F 스타일, 냉철한 T 스타일 등 대화/코칭 성향, PM·풀스택·QA 등 직무, 검증 등급, GPT·Claude 등 사용 모델/도구를 구분해 고른다.
3. **AI 대화가 아니라 검증 가능한 실제 일:** 계약된 권한 안에서 계획·문서·업무 실행/진행 관리, 결과 검수·수락과 근거/상태/비용을 남긴다. PM은 필요한 경우 다음 행동을 주도적으로 제안한다.

**장기적 인력사무소 콘셉트:** 동일한 카탈로그 AI 직원은 여러 고객 프로젝트를 수행할 수 있고, 고객이 **직원 경력 적립에 동의한 검증된 업무**만 직원의 경력일수/성취/평가에 합산할 수 있다. 직원 등급/단가는 축적한 신뢰도와 별도의 역량 검증을 바탕으로 달라진다. 직원은 프로젝트의 비공개 문서나 타 고객 정보를 기억·전파하는 존재가 아니다.

## 3. 기존 PlanOS KEEP — '기본 AI 기획'의 정확한 의미

**CURRENT 자산(전체 동작 재검증 필요):**
- 프로젝트/기존 사용자 로그인·프로젝트 생성 및 기존 AI 인터뷰 흐름.
- 기존 5종 기획 산출물: PRD(`prd`), UI 기능명세(`ia`), 숨김 화면목록(`screen_list`), 정책(`policy`), Cursor 프롬프트(`cursor-prompt`). 실제 현 코드 생성/탭/내보내기는 단계별 테스트로 확인한다.
- 문서 AI 채팅 편집·연쇄 재생성, 사용자 직접 편집, 자동저장/버전/복원, 댓글·협업, 기존 MD/ZIP/프롬프트 복사 기능.
- 기존 프로젝트·문서 ID, 데이터 보존, 딥링크 유지. 신규 인력사무소 때문에 기존 인터뷰/문서 화면을 제거하거나 교체하지 않는다.

**경험의 의미:** 사용자는 처음부터 직원 채용·모델 선택이 필수인 복잡한 화면을 마주할 필요가 없다. **기본 AI 기획으로 시작 → 프로젝트 진행 → 그 시점에 필요한 AI 직원 추가/교체/정식 채용**이 가능한 구조다.

**표현 보정:** 'Solo'나 '직접 기획'은 **전담 PM에게 상시 운영을 위임하지 않는 상태**를 말하며, 'AI 없음/무료 무제한'을 뜻하지 않는다.

## 5. AI 인력사무소 상세 서비스 모델

### 5.1 AI 직원의 여섯 가지 독립 차원

1. **직무(무엇을 맡나):** PM, 서비스기획, UX/UI, 풀스택 개발, 프론트엔드, 백엔드, QA, 데이터/리서치, 콘텐츠/마케팅, 운영 등. 각 직무는 허용 도구·요구 산출물·검수 기준이 다르다.
2. **업무 성향/캐릭터(어떻게 안내하나):** 공감·상냥한 F 스타일, 논리·직설 T 스타일, 차분한 분석형, 적극적인 실행형, 창의형, 꼼꼼한 검증형. 실제 MBTI 진단이나 인격 인증으로 오인시키지 않는다.
3. **프로젝트 리딩 강도:** 질문하며 같이 진행 / 먼저 계획을 제안하고 승인받기 / 권한 내 반복 업무 위임. 성향은 말투, 리딩은 실행 권한의 UX다.
4. **검증 경력 등급:** 초급·중급·고급. 고객이 동의한 **실제 프로젝트 수행/검증 활동일수**, 수락 산출물, 역량 검증 및 고객 평가에 기반한 신뢰 수준.
5. **AI 모델/실행 패키지:** GPT 계열, Claude 계열 등 `provider+model_id`, 지원 컨텍스트·도구 호출/사용량·실제 원가. 직원의 성격/경력과 **독립**이다. 고급 경력 ≠ 특정 고성능 모델 사용.
6. **채용 형태/담당 범위:** 단발 업무, 프로젝트 전담, PM 정식 채용(선택된 1개/복수 프로젝트). 수행할 수 있는 범위는 계약·프로젝트별 권한·사전 승인에 종속된다.

**직원 ID 정체성:** 직원 카탈로그의 고유 식별자/경력 원장을 유지하고, 고객별 채용 계약·기본 모델·성향 미세 조정·프로젝트 배정을 분리한다. 한 고객의 비공개 컨텍스트가 다른 채용 세션에 유입되면 안 된다. 모델 교체가 자동 경력 초기화나 경력 승계를 뜻하지 않는다. 새 모델의 작업 역량은 별도 평가한다.

### 5.2 직원 목록·상세 화면의 필수 정보

- 프로필 카드: 가상 이름/아바타, 직무, 작업 스타일/리딩 강도, 경력 등급, **동의된 범위의** 검증 활동일수/프로젝트 수, 평가 표본 수, 지원 도구/모델 및 가격 범위.
- 프로필 상세: 할 수 있는 업무/불가능 업무, 검증된 수행 시나리오/이력, 성격 시연(같은 문제에 F vs T 답변 예시), 실제 모델 제공자, 데이터 처리 고지.
- 탐색 필터: 역할→등급→성향→모델/도구→사용자 예산→채용 형태. 모델이 미지원하는 작업은 선택 불가/사유 표시.
- 채용 CTA: **단발 의뢰 / 프로젝트 전담 / 정식 PM 채용 / 현재 직원 교체**. 각 행위의 계약·업무 범위·기존 작업 영향이 달라야 한다.
- '가상 직원 경력 설정'과 '검증된 실경력'의 라벨을 분리하고, 수행 증빙이 없으면 '검증 전' 표시. AI 캐릭터에게 실제 학력/이전 고용주의 인간 경력을 허위로 표시하지 않는다.

### 5.3 초기 직원 프로필 예시 (기획용 가상 시안)

| 캐릭터 | 직무 | 성향 | 리딩 방식 | 모델 후보 | 실제 산출물 |
|---|---|---|---|---|---|
| 하루 | PM | 상냥한 공감형 | 상황 공감→작은 다음 행동→승인 요청 | GPT 계열 검증 전 | 프로젝트 우선순위/체크인 |
| 태오 | PM | T형 직설·팩트형 | 문제점 지적→선택지→실행 순서 | Claude 계열 검증 전 | 위험·일정·우선순위 |
| 로이 | 풀스택 | 분석·구현 중심 | 코드/의존성 진단→수정안→테스트 | 모델 비교 전 | 코드 변경/PR/검증 로그 |
| 린 | QA | 엄격한 검증형 | 실패 재현→결함 관리→재검수 | 모델 비교 전 | 결함·테스트 보고서 |

이는 실제 구현·실제 공급자/등급 인증·가격 확정이 아니며 캐릭터 이름/직무 구성은 최종 카탈로그 결정 전에 바뀔 수 있다.

## 6. 채용 유형별 서비스 경험

| 구분 | 단발 AI 업무 | 프로젝트 전담 직원 | 정식 채용 PM |
|---|---|---|---|
| 계약 단위 | 검수·개발 등 특정 작업 | 선택한 프로젝트 내 지속 업무 | 선택한 1개 또는 여러 프로젝트 |
| 주도성 | 의뢰된 범위만 | 담당 직무의 다음 단계 제안 | 프로젝트 목표·우선순위·직원 조율 |
| 진척 화면 | 작업별 결과 | 프로젝트 직원 활동 | 여러 프로젝트 통합 운영실 |
| 변경 | 취소/재의뢰 | 담당자 교체·해임 | 프로젝트 배정/제외·PM 교체/해임 |
| 안전 게이트 | 수행 승인·자료 스냅샷 | 계약/예산/권한 재검증 | 프로젝트별 격리·승인·예산 상한 |

**정식 PM 실제 책임(TARGET)**
- 맡은 프로젝트들의 상태/문서/업무 현황을 읽고 막힌 업무·위험·우선순위를 제시한다.
- 계획·마일스톤·업무를 제안/편집하고 필요 시 개발자·QA 등 다른 직원에게 **업무 의뢰 초안**을 만들거나 승인된 범위에서 배정한다.
- 결과가 제출되면 검수 근거를 확인하고 사용자에게 수락·반려·추가 승인 필요 사항을 보고한다.
- 복수 프로젝트 통합 요약을 제공하더라도 각 프로젝트의 문서·계약·권한·비용은 독립 관리한다.
- 실제 주기적인 자동 실행은 scheduler + worker + 재접속 가능한 작업 기록이 구축된 후에만 가능하다. 채팅창에서 '계속 관리 중'이라고 말한다고 자동 운영이 되는 것은 아니다.

**담당 프로젝트 선택:** 기본 OFF의 개별 체크/선택 배정. 미래 생성 프로젝트와 미선택 프로젝트를 자동 포함시키지 않는다. 사용자는 언제든 배정 해제·PM 교체 가능하며, 이때 진행 중 실행의 취소/정산/승인 이전과 권한 회수 절차를 보여 준다.

## 7. 고객 경력 동의 — 채용 시와 프로젝트 종료 시

### 7.1 채용 시 선택을 두 층으로 분리

**A. 이 프로젝트의 AI 직원 참여 사실·검증 실적을 해당 직원의 경력/승급에 사용할까요?**
- **허용** → 실제 작업 로그와 수락/검증을 근거로 경력일수·완료 건수 후보를 계산. 직원별/프로젝트별 동의 유지.
- **허용 안 함(기본값)** → 계약 수행에 필요한 작업 로그는 보안/감사/청구 목적으로만 관리하고 경력·등급·추천/홍보에는 반영하지 않는다. 서비스 품질·계약 가격의 불이익 없음.

**B. 허용할 경우 해당 프로젝트 수행 정보를 다른 채용 고객에게 어느 정도 보여 줄까요?**
- **공개:** 고객이 승인한 제목·업종·허용 성과/기간 등 **명시적으로 선택된 필드**만.
- **익명 공개:** 고객·브랜드·URL·고유 단서를 제거한 직무/검증 결과만(재식별 우려가 있으면 공개 불가).
- **비공개(기본):** 프로젝트 식별·개별 내용은 외부 프로필에 공개하지 않는다. A가 허용일 때만 비공개 승급 내부 집계 사용 가능; 집계된 활동일수/프로젝트 건수 배지를 외부 공개하는지 별도 선택.

**독립 추가 선택:** 프로젝트명·로고·원본 산출물 포트폴리오 게시, 익명/실명 고객 후기, 평점 배지 공개, 추천/랭킹/홍보 2차 이용, 외부 모델 학습 등은 각각 별도 권한이다. **경력 허용=고객 원문·코드·아이디어·개인정보 공개/재학습 허용이 절대 아니다.** 법적으로 유효한 데이터 보존·삭제·철회 범위는 출시 전 국내 법률 검토 필요.

### 7.2 업무 진행·완료·철회

- 진행 중: 직원 ID/프로젝트 ID/고유 작업 이벤트와 해당 모델·검증 상태를 **프로젝트별 독립** 로그에 기록. 고객의 동의 버전을 붙여 경력 계산 대상인지 판단한다.
- 종료 시: 고객에게 실제 작업/활동일수 후보/산출물 수락/공개 미리보기/평점·후기를 제시하고 범위를 최종 확정한다. 응답 없음=공개 확대 동의 아님.
- 동의 축소·철회: 공개/익명 사례/집계·랭킹 노출 중지·수정; 적립 동의까지 철회하면 직원 경력·승급을 재계산한다. 서비스 계약/감사 로그의 최소 보존은 별도 적법 근거로만 처리하며 마케팅에 전용 금지.
- 채용된 PM이 여러 프로젝트를 맡아도 **각 프로젝트·각 AI 직원별** 동의, 경력, 결과 수락을 분리하여 관리한다.

## 8. 실제 경력일수·완료 실적·승급

**검증 활동일수:** '계약한 지 며칠'이 아니라 **검증 가능한 업무 수행 이벤트가 발생한 날짜**를 센다. 같은 직원이 같은 날짜 여러 프로젝트에서 일했어도 고유 활동일수는 **1일**로 중복 제거한다. 승급에 포함할 수 있는 일수는 고객이 해당 직원 경력 적립에 허용한 프로젝트만. 사용자 세션 유지, 시스템 대기, 테스트 fixture, 허위 생성 실행을 경력으로 쌓지 않는다.

**서로 다른 지표**
- 검증 활동일수 (`unique_active_days`): 실제 참여의 폭.
- 수락된 프로젝트/산출물: **결과의 완성도**; 계획만 제시하고 종료된 프로젝트는 완료 성공 건으로 세지 않는다.
- 검증 업무 유형·도구·난도: 그 직원이 할 수 있다고 **주장 가능한 작업 범위**.
- 고용주 후기·별점: 선택적 평가, 표본/분쟁/허위후기 필터 필요. 평점 미존재를 0점처럼 보이지 않는다.
- **검증 경력 등급**은 이렇게 실적이 쌓이며 변하지만, 사용 중인 GPT·Claude 모델 자체가 사용 경험으로 자동 학습하거나 지능이 올라갔다고 말하지 않는다.

**검증 등급 제안(운영 수치는 미확정):**
| 단계 | 검증 활동일수 예시 | 함께 필요한 조건 예시 | 의미 |
|---|---:|---|---|
| 초급 | 0~29일 | 기초 작업 검증/초기 수락 기록 | 경험 적고 저렴한 인재 |
| 중급 | 30~179일 | 수락 프로젝트 3건+직무 역량 시험 | 반복 실무 기록 |
| 고급 | 180일 이상 | 수락 프로젝트 10건+심화 역량/품질 검증 | 축적된 신뢰/복잡한 작업 실적 |

**원칙:** 기간만 충족했다고 승급하지 않고 **경력일수 AND 성공 수락/성과 AND 최신 역량 평가**를 모두 충족해야 한다. 모델 변경 시 기존 경력 보존, 새 모델의 도구 능력 검증은 별도. 모든 승급/철회/재평가는 규칙 버전·증빙을 감사 기록에 보존한다. 수치·이름은 고객 실험 전 최종 결정 아님.

### 9.2 경력 등급별 상대가격 규칙

- **초급은 같은 직무·같은 모델 패키지·같은 계약 조건의 중급/고급보다 저렴하게** 책정한다는 것이 제품 방향이다.
- 경력 등급과 사용 모델/도구 원가를 분리해서, **초급 직원 + 비싼 모델**과 **고급 직원 + 저렴한 모델**을 비교할 수 있도록 한다.
- 등급과 채용 가격은 공개 전에 **원가/마진·고객의 구매 의사·품질 차이**를 검증한다. 가격 숫자·배수·최저 요금은 현재 정하지 않는다.
- 계약 개시 당시 **직원 등급·모델·단가·사용량/기간·상한**을 스냅샷으로 고정한다. 직원이 계약 중 승급해도 기존 계약을 자동 인상하지 않는다. 갱신/새 업무에 변경 가격을 재고지하고 고객 승인을 받는다.
- 경력 공개·후기 제공을 가격 할인/필수 조건으로 강제해 고객의 비공개 선택에 불이익을 주지 않는다.
- 환불·취소·중복 실행·토큰 원가 미확인/후불 청구 정책은 법무·실측·운영 승인 전 정식 서비스에 적용 금지.

### 9.3 수익성 실험(가설)

- 1차: 기존 AI 기획 사용자에게 **전문 검수 1건의 산출물 가치**를 확인하는 제한 파일럿.
- 2차: 같은 업무를 맡았을 때 **초급 저가 vs 중급/고급 프리미엄**에 고객이 어떤 품질 신호에 돈을 지불하는지 테스트.
- 3차: 전담 PM에게 배정할 프로젝트 수·주간 진척 관리 횟수·사용자 개입/수락률이 **지속적 가치**를 만드는지 검증.
- 4차: 모델 공급자별 실제 도구 호출 비용·재시도 원가·개입 비용/업무당 마진을 실측. 특정 요금·매출 목표를 검증 없이 확정하지 않는다.

## 11. 대표 고객 여정 — 성공·실패·복귀

### 시나리오 A: 기본 AI 기획 이용 후 단발 전문 직원 투입
1. 기존 AI 인터뷰에서 기획 문서 생성→사용자가 직접 채팅으로 수정.
2. 진행 허브에서 '기획서 검수 직원 찾기'→직무/성향/모델/경력/가격 비교.
3. 직원·검수 대상 문서/버전·권한·비용 확인→해당 프로젝트 경력 적립/공개 선택(거부 가능).
4. 계약·모델 전송/비용/실행 별도 승인 뒤 한 번의 검수 실행.
5. 보고서의 근거 확인→수락/수정 요청→원본 문서·기존 채팅 흐름 유지.
6. 실제 참여 이벤트 및 고객 동의가 있는 경우 경력일수 적립, 후기/공개는 종료 시 최종 확인.

**실패:** 문서 수정으로 스냅샷이 달라지면 지난 승인으로 실행 차단, 다시 자료 선택/승인. 네트워크 불명확 상태에서 이중 실행·이중 청구 금지.

### 시나리오 B: 성향 맞는 PM 정식 채용 후 여러 프로젝트 위임
1. 직원 후보 하루(공감형)/태오(직설형)의 **같은 업무 피드백 시연**을 비교.
2. 모델/도구·검증 경력·단가·수행범위 확인하고 PM 채용.
3. 프로젝트 A와 B만 선택해 배정, 프로젝트 C는 제외. 업무 쓰기/보고/다른 직원 요청 범위 별도 설정.
4. PM이 A/B의 기존 AI 기획 문서·업무 현황 읽기→우선순위·계획·담당 직원 제안.
5. 사용자는 계획/실행 승인을 선택하고 언제든 원래 문서를 직접 편집하거나 PM 성향 조정.
6. PM은 승인된 작업만 조율·실행하고 프로젝트별 검수 결과를 통합 브리핑. C 자료 접근은 거부.
7. PM 교체/해임 시 새 실행 즉시 차단, 이미 기록된 업무·문서·채용 경력/청구 이력 보존·안내.

**실패:** 권한이 철회되거나 비용이 초과되면 새 작업 중지, 승인함에 이유/재개 방법 표시. **단순 채팅 응답만으로 주기 자동 실행 완료라고 주장 금지.**

### 시나리오 C: 초급 직원 성장·가격과 고객 공개 통제
1. 초급 풀스택 직원 저가 채용(실제 가격 미정). 프로젝트 경력 적립은 허용하되 외부 공개 '익명' 선택.
2. 직원은 검증된 작업일/산출물/고객 수락을 축적. 프로젝트별 일수 중복 제거, 임의 대기/테스트 이벤트는 제외.
3. 수락 결과·고객 후기/공개 미리보기 확인. 정해진 경력일수+완료 결과+역량 평가 충족 시 승급.
4. **현재 계약 단가 불변**. 다음 고객 채용/갱신에 중급 가격 표시.
5. 고객이 공개를 철회하면 승인한 공개 레퍼런스/후기 삭제·정정; 적립 자체도 철회하면 경력/등급 재산정.

**실패:** 고객의 원본 소스/비밀정보/모델 데이터가 이후 다른 고객 직원 컨텍스트로 넘어가지 않음.

## 12. 서비스 실행 엔진과 핵심 데이터/권한 (개념 계약)

**직원 정체성(`staff_identity`) ≠ 사용자별 고용 계약(`staff_engagement`) ≠ 프로젝트 배정(`assignment`) ≠ 실행 모델(`model_route`) ≠ 작업(`run`) ≠ 경력 원장(`experience_ledger`).**

핵심 논리 데이터:
- **직원:** 고유 ID/가상 이름/직무/성향/검증 역량/활성 모델·도구 후보/공개 프로필.
- **계약:** 고객 ID·직원 ID·단발/전담/정식 PM, 기간·현재 등급/가격·예산 스냅샷·상태·동의 버전.
- **배정:** 계약 ID와 **명시적 프로젝트 ID 목록**; 프로젝트별 역할·읽기/쓰기/실행·철회.
- **자료/계획:** 프로젝트·문서 ID, revision/digest, 승인 계약·계획 버전 및 임의 수정 시 stale 처리.
- **작업/결과:** 의뢰한 직원·model_provider/model_id/도구·idempotency key·실제 실행 기록·비용/산출물 버전/검증·사용자 수락.
- **경력:** 직원×프로젝트×작업의 검증 이벤트, 고객 적립 동의·공개 범위/목적·철회, 고유 활동일수, 수락 건수, 리뷰, 승급 내역, 가격 변경 이력. 플랫폼 공개 프로필과 내부 작업 감사기록을 별도 읽기/보존 정책으로 관리.
- **모델 라우터:** 업무 능력/툴 호환성·예산·공급자별 데이터 전송 허가를 검사; 다른 공급자 자동 fallback 시 고객 동의 없이 자료 재전송 금지.

**권한:** owner만 계약/실행 예산/최종 수락 승인. editor는 허용된 기획/업무/계획 초안 작성, viewer는 열람. 직원/PM은 부여된 역할·배정 프로젝트·툴 scope 이외 접근 불가. 실제 JWT/RLS/서버 필드 allowlist로 검증해야 하며 화면 숨김만으로 보안 완료가 아니다.

**데이터 유출 방지:** 어떤 고객이 직원의 경력 축적에 허용했다고 해서, 타 고객 프로젝트에 문서 내용·코드·채팅/고객 정체성을 모델 컨텍스트로 복사하거나, 외부 AI 제공자 학습에 사용하도록 허용된 것은 아니다. 공개 허용 필드만 공개 프로필에서 사용한다.

## 14. MVP의 현실적인 단계별 검증·범위 통제

**Phase 0 / G1(별도 P0):** 기존 저장/복원·동시 편집·채팅 쓰기·RLS 안전성 회귀를 먼저 통과시켜 신규 직원이 고객 문서에 안전하게 접근/수정하도록 한다.

**제품 UX Mock(운영 DB·유료 모델 미연결 병행 가능):**
1. PM/풀스택/QA 3직무×공감형/직설형 2스타일로 6가지 대표 프로필 비교; 가상 경력 및 검증 전 상태 고지.
2. 직원 프로필→모델/툴/현재 경력등급→단발/정식 채용 선택→배정 프로젝트 1개/복수→경력 적립/공개 동의(기본 거부).
3. PM의 배정 프로젝트 통합 운영실 Mock→제안/승인함→사람 문서 직접 수정과 직원 투입 공존.
4. 프로젝트 종료 시 직원 경력일수/수락 결과/고용주 평가·공개 최종 확인 Mock.
5. 초급·중급·고급 승급/계약 단가 유지·갱신 가격 변경 Mock.

**서버/격리 DB 통합:** 역할별 Auth/JWT/RLS·동시성, 다중 프로젝트 명시적 배정, 모델 라우팅 공급자 동의, 승인된 단발 실행, 직원 수행 이벤트 원장·승급 계산, 리뷰 조작 방지, 공개 필드 allowlist/철회 테스트.

**실제 AI 도구/운영:** 모델 공급자 선택 및 사업자/고객 데이터 처리·예산/원가 확정 이후 제한 파일럿. PM 주기적 자율 실행은 워커·스케줄·회복·종료 처리 검증 후. 초기 1개 검수 직무 실모델 E2E와 다중 직무 카탈로그 UX 검증을 혼동하지 않는다.

**검증 완료의 정의:** 문서 작성≠코드 구현≠격리 DB/브라우저 E2E PASS≠실제 유료 모델 작동≠운영 적용. 기능별 상태를 명확히 기록한다.

## 15. KPI·가설 검증과 사업 실행 관점

- **기본 기획 활성:** 신규 사용자의 AI 인터뷰 시작→5종 산출물 생성/보존→첫 업무 생성률.
- **인력사무소 매칭:** 직원 직무/성향/모델 탐색→프로필 비교→단발 업무·정식 채용 전환률, 채용 이탈 이유.
- **실제 진행:** PM 제안 수락률, 승인 이후 작업/산출물 수락률, 오류/재작업/사용자 개입 횟수, 여러 프로젝트 계속 이용률.
- **경력 성장·신뢰:** 경력 적립 허용률, 공개/익명/비공개 선택, 수락 산출물·활동일수, 평가 표본, 승급 시 검증 통과율, 후기 신뢰성/동의 철회.
- **가격·수익:** 초급/중급/고급의 동일 조건 의향 가격, 수락 완료 업무당 공급자 원가+운영 원가, 매출총이익·이중 과금/환불·계약 갱신률.
- **고객 보호:** 부적절 공개/권한 넘김/무승인 모델 호출 0, 문서 유실/복원·중복 이벤트·경력 부풀림 0 목표.

**실험:** 목표 사용자 5~10명 정성 인터뷰 → '기본 AI 기획→직원 선택→실제 결과' 사용성/의향 검증 → 검증된 1직무 실행 원가 측정 → 등급/가격 비교 테스트 → 자율 PM 다중 프로젝트 정기 가치 검증. 목표 숫자는 아직 수행 실적/시장 수요 증거가 아니다.
