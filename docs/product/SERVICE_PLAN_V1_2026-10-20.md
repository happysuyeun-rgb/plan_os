# PlanOS 3.0 × AI 인력사무소 — 통합 서비스기획서 v1.0

**작성·검토:** 2026-10-20 · **상태:** 제품 운영 방향과 MVP 범위에 대한 구체 설계. 상용 판매/요금/외부 데이터 처리/운영 승인 전. 기존 PRD v0.3의 요구사항을 실행 가능한 서비스 상품과 고객 여정으로 재구성한 제품 기준안.

## 1. 서비스의 본질과 해결할 문제
**서비스 한 문장:** 개인 또는 소규모 팀이 프로젝트를 정리하고, 승인한 범위에서 AI 전문 역할에게 구체적인 업무를 맡긴 뒤, 근거가 있는 결과물을 검수할 수 있는 통합 프로젝트 운영 서비스.

고객이 사는 가치는 'AI 직원 수'가 아니라 **일의 완결성**이다. 기존 채팅의 산발적 대화, 산출물 근거 부재, 실행 상태 소실, 무단 변경/비용 불확실성을 해결한다. 제품 카피의 '고용'은 비유이며 실제 인간 근로계약·고용관계는 제공하지 않는다.

**주 사용자:** ① 1인 창업자 ② 프리랜서·제작자 ③ 2~5명 소규모 팀 리더. 첫 번째 유료 전환 가설은 '기획서 검수 업무를 반복하는 사용자'. 수요·가격·전환률은 미검증이므로 사실처럼 표현하지 않는다.

## 2. 제품 제공 형태 / 서비스 모드
- **Solo:** 프로젝트·문서·업무·이력 관리. AI 사용/모델 전송/유료 비용 없이 사용 가능한 기반.
- **AI Team:** 동일 프로젝트에 계약·예산·권한에 의해 제한되는 AI 역할을 붙여 작업을 실행. Solo와 같은 문서·업무 ID를 사용하여 모드 전환 시 복제나 손실 없음.
- **AI 인력사무소:** 검증된 AI 역할의 프로필·권한·제한·비용 조건을 공개하고 프로젝트에 배치하는 UX. 역할별 능력을 과장하거나 허구의 경력을 표시하지 않는다. 고객용 프로필/면담 UI는 첫 실행 루프가 동작한 후 공개.

**초기 상품 구성(제안):**
| 상품 | 전달되는 가치 | 상용 출시 전 조건 |
|---|---|---|
| 무료/기본 프로젝트 운영 | 기존 PlanOS 프로젝트/문서 관리 + 신규 사람 업무 보드 | 실제 무료 제공량·요금제 한도 별도 확정 |
| 기획 검수 AI 단건 실행 | 프로젝트 내 선택 문서 2건 이상 교차 검사, 근거 있는 비공개 검수 보고서 | 실제 모델·원가·상한·고지·약관·검증 통과 |
| 팀 플랜(후속) | 프로젝트 멤버·승인/작업 위임/공유 고도화 | 역할별 권한·팀 비용/감사 정책과 가격 검증 |
| 추가 AI 전문 역할(후속) | 리서치·콘텐츠·개발 등 역할별 산출물 | 역할마다 실제 도구·안전성·검증 능력 확보 |

가격, 월 제공량, 무료 호출 횟수, 결제수단은 아직 설정하지 않는다. 공급자 실비와 고객 요금은 별도 개념이다.

## 3. 핵심 사용자 여정과 화면별 가치
| 단계 | 진입/행동 | 사용자가 확인할 사실 | 실패·회복 |
|---|---|---|---|
| 1 진입 | 프로젝트 선택/신규 작성 | 기존 문서·업무·멤버십 유지 | 접근 거부·삭제 프로젝트 안내 |
| 2 업무 | 업무 생성/목표·완료 기준 지정 | 담당·상태·이력 | 저장 실패면 입력 복구, 중복 생성 방지 |
| 3 AI 선택 | 기획 검수 AI 역할·검사 범위 안내 | 허용 도구/원문 전송/금지 작업 | 지원하지 않는 작업은 명시 |
| 4 자료 선택 | 같은 프로젝트 문서 2개 이상 | 선택 문서 ID·버전/해시·비용 발생 전 미리보기 | 변경·삭제·미저장 문서 재선택 |
| 5 계약 | owner 계약·개인정보 처리·모델 공급자·예산 상한 동의 | 이용약관 버전·문서 범위·예상/상한 비용 | 무동의면 유료 호출 0 |
| 6 PM | 사람이 작성한 초기 무과금 계획 또는 승인된 범위의 유료 AI 생성 계획 | AI 생성 여부 정확한 표기, 계획 버전 | 재작성은 재승인 |
| 7 실행 | owner가 최종 실행 승인 | 실행 ID·대기/수행/검사/장애 상태 | 브라우저 종료 후 재접속, 중복 실행 방지 |
| 8 결과 | 근거/출처가 표시된 비공개 보고서 확인 | 확인된 근거 vs 미확인 가정, 비용 | 근거 부족/실패 시 재검수 요청 |
| 9 수락 | owner 수락·반려·수정 요청 | 수락한 보고서 버전·감사 로그 | 이전 수락을 수정본에 자동 적용 금지 |
| 10 재방문 | 보고서·업무·다음 행동 확인 | 사용 가능한 산출물과 후속 과제 | 접근 권한 변동 재검증 |

**우선순위:** S1 사람 업무 CRUD → S2 선택 문서 고정 → S3 동의/계약 → S4 계획 승인 → S5 서버 작업 → S6 보고서 검수 → S7 통합 E2E. Phase 0 데이터 유실/보안 결함은 별도 레인에서 병행. 제품 기능은 UI/mock-only, 개발 DB 통합, 운영 반영을 분리하여 표기.

## 4. MVP 기능 수용 기준
- 같은 프로젝트의 업무 생성/수정/상태 전환/새로고침 재조회, 프로젝트별 권한/RLS.
- 선택 문서 2건 이상, 해시/리비전 스냅샷 일치. 서버 원문 변경 시 오래된 승인 실행 중지.
- 승인 전 실제 모델 호출 금지. owner 계약·계획·실행 승인 각각 다르게 기록.
- 영속 run과 중단/재시작 복구, 멱등성/예산 예약/원장, 근거 있는 비공개 보고서.
- 원본 문서 불변. 자동 출처 검증과 인간 의미 검수·수락 분리.
- 다른 프로젝트 문서·실행·비용 조회 불가. 기존 PlanOS 문서·버전·협업·휴지통 기능 회귀 통과.
- 한 명 이상의 파일럿 사용자에게 실제 산출물 1건 이상 검수받고 작업 성공/재작업·사용성 기록. **성과 수치는 검증 전 기재 금지.**

## 5. 수익모델과 전환 실험
**핵심 가설:** 고객은 AI 직원 자체보다 '근거를 확인할 수 있는 완료된 업무'에 비용을 지불한다. 기본 프로젝트 관리 → AI 검수 결과 샘플/입력 검토 → 유료 검수 실행으로 전환. 초기에는 한 가지 유료 작업 상품만 검증하고 기능별 과금·구독 혼합은 고객 조사 후 판단한다.

**실험 순서:** ① 고객 5~10명 인터뷰(가설 검증용 목표, 아직 수행 안 함) ② 사용 빈도가 높은 문서 검수 사례 수집 ③ mock UI에서 가치/가격 이해 테스트(실과금 없음) ④ 원가 실측 ⑤ 명시적 가격·약관 승인 후 제한 유료 파일럿. 특정 인터뷰 수는 확정 운영 의무가 아닌 실험 목표.

**지표:** 프로젝트→첫 업무 생성률, 자료 선택→계약 동의 전환률, 승인→실제 실행 성공률, 검수 보고서 수락/반려율, 업무별 재작업률, 원가/수락된 결과물, 재방문 비율. 단순 채팅량·문서 생성량을 핵심 성공 지표로 사용하지 않는다.

## 6. 지원·고객 커뮤니케이션 설계
- 상태 안내: 신청됨 / 승인 대기 / 수행 중 / 확인 필요 / 사용자 수락 완료를 분리. 서비스 수준의 과장된 'AI 완료' 표현 금지.
- 장애 안내: 프로젝트·run ID, 단계, 다음 사용자 행동(안전 재시도/지원 요청), 추가 과금 가능성 또는 미확정 상태 표시. 시스템 내부 비밀·타인 데이터 노출 금지.
- 고객 문의 분류: 접근·계정 / 잘못된 보고서 / 실행 실패 / 비용 이의 / 개인정보·삭제.
- 공지·변경: 기능·모델·데이터 공급자·요금/보존 정책의 실질적 변경은 시행 전 확인/재동의 필요성 평가.

## 7. 결정·승인 게이트
**설계 기준으로 즉시 개발 가능한 것:** S1 업무 CRUD, S2 문서 선택/해시/권한 테스트, mock S3/S4, 서버 mock 실행 PoC. 이들은 상용 정책·외부 API 비용 승인 없이 별도 개발 환경에서 진행.
**상용 호출/출시 전 미확정:** AI 역할 최초 공개 승인, 실제 공급자·워커 환경, 데이터/국외 이전 처리, 요금·과금·환불, 고객 데이터 보존/삭제, 고객 지원/약관/개인정보 고지, main/운영 DB migration/배포 승인.
**소유자 검토 과제:** MVP 첫 상품, 무료 범위, 구독 vs 단건 과금, 공개 권한·고객 지원 범위. 담당 AI가 임의로 법적 약관이나 가격 숫자를 승인한 것으로 처리하면 안 된다.
