# PlanOS 3.0 — 권한·승인 정책 매트릭스

**최초 작성일:** 2026-10-16  
**최종 수정일:** 2026-10-16  
**문서 버전:** v0.1  
**진행 상태:** TARGET 정책 초안 / 보안 검토·DB 재현 전  
**상위 기준:** [PRD](PRD.md) · [업무 흐름](TASK_FLOWS.md) · [화면 명세](../ux/SCREEN_SPEC.md)  
**범위:** 사람 계정, AI 서비스 계약, PM/전문 AI 도구 실행의 서버 권한. 현재 RLS가 이를 충족한다는 의미는 아님.

## 1. 권한 결정 원칙
1. **기본 거부(default deny):** 인증·프로젝트 멤버십·계약·도구·승인·예산 중 하나라도 검증되지 않으면 실행하지 않는다.
2. **서버가 최종 결정:** 화면의 버튼 비활성화는 안내일 뿐, 서버 API/RLS/워커에서 다시 검증한다.
3. **프로젝트 격리:** 프로젝트 A의 멤버/AI가 프로젝트 B의 문서·도구·로그·계약에 접근할 수 없다.
4. **AI는 사용자 계정이 아니다:** AI worker는 별도 서비스 주체이며 사용자 권한을 무제한 위임받지 않는다. 명시된 프로젝트·계약·작업·도구 범위만 행사한다.
5. **최소 권한:** 사용자 역할 + 계약 범위 + 업무 목적 + 자원 소유권 + 비용/위험 조건을 모두 만족해야 한다.
6. **감사 가능성:** 승인, 권한 변경, 도구 호출, 실패, 수락을 actor/subject/project/resource/trace/시각으로 연결한다.
7. **권한 변경 즉시 적용:** 멤버 제거·계약 해지·승인 철회 시 새로운 도구 실행 차단. 이미 진행 중인 작업의 취소 가능 여부는 별도 기록한다.

## 2. 사용자 역할과 행위 매트릭스

기호: **A** 허용, **C** 조건부, **D** 거부. `C`는 하단 조건을 만족할 때만 허용한다.

| 행위 | owner | editor | viewer | outsider | AI PM | 전문 AI |
|---|---|---|---|---|---|---|
| 프로젝트 읽기 | A | A | A | D | C | C |
| 프로젝트 목표/문서 수정 | A | A | D | D | C | C |
| 사람 업무 생성·수정 | A | A | D | D | C | C |
| AI 역할 탐색·프로필 읽기 | A | A | A | C | C | D |
| AI 계약 생성·조건 승인 | A | D | D | D | D | D |
| AI 팀 배치·계약 해지 | A | D | D | D | D | D |
| PM 계획 초안 작성 요청 | A | A | D | D | C | D |
| 실행 계획 최종 승인 | A | C | D | D | D | D |
| AI 실행 요청·위임 | A | C | D | D | C | D |
| AI 실행 로그/산출물 읽기 | A | A | C | D | C | C |
| 저위험 초안 작성 도구 | A | C | D | D | C | C |
| 배포·삭제·대외 발송·결제 승인 | A | D | D | D | D | D |
| 산출물 최종 수락/반려 | A | C | D | D | D | D |
| 예산 상한·결제 설정 변경 | A | D | D | D | D | D |
| 계약/프로젝트 비용 읽기 | A | C | D | D | C | D |
| 프로젝트 휴지통 이동·복원 | A | D | D | D | D | D |
| 본인 댓글 작성·수정·삭제 | A | A | C | D | D | D |
| 타인 댓글 수정·삭제 | D | D | D | D | D | D |
| 알림/반응 본인 상태 변경 | A | A | C | D | D | D |
| 프로젝트 멤버 초대·제거 | A | D | D | D | D | D |

**조건부(C) 규칙**
- editor의 계획 승인·AI 실행·결과 수락: 프로젝트 owner가 **명시적으로 위임한 범위/금액/만료** 내에서만. **MVP 기본값은 owner만 허용**.
- viewer의 댓글/반응/실행 로그 조회: 해당 프로젝트 정책과 본인 권한에 따라. **MVP는 읽기만 기본**, 댓글은 별도 허용 시.
- AI PM/전문 AI: 유효 계약 + 역할 capability + 지정 작업 + 자원 접근 범위 + 예산 + 승인 + 서버 allowlist. **AI는 고위험 작업을 직접 승인할 수 없음**.
- 타인 댓글 수정은 기본 금지. 신고/관리자 삭제는 별도 moderation 이벤트/권한으로 분리.
- outsider의 역할 프로필 열람은 공개 카탈로그 정책이 허용할 때만, 프로젝트 정보와 완전히 분리.

## 3. 도구 위험 등급과 승인 정책

| 등급 | 예시 | 실행 정책 | 로그/증빙 |
|---|---|---|---|
| R0 — 읽기 | 승인된 공개 문서/프로젝트 내 허용 자료 조회 | 계약·권한·데이터 범위 검증 후 가능 | 읽은 자원 ID, 범위, 결과 |
| R1 — 내부 초안 | 신규 문서 초안, 업무 계획, 검증 가능한 비공개 산출물 | 활성 계약·예산 내에서 계획 승인 후 실행 | 생성 버전, 검증 결과, 비용 |
| R2 — 내부 변경 | 기존 문서 덮어쓰기, 작업 상태/데이터 변경, 코드 수정 | 구체적 변경 대상·diff 사전 승인(정책별 예외는 별도 결정) | 변경 전후·승인 ID |
| R3 — 외부 영향 | 배포, 병합, 외부 발송, 결제, 데이터 삭제, 외부 공유 | **owner 명시적 행위별 승인 필수**. 기본 자동 실행 금지 | 대상/범위/예산/만료/실제 결과 |

**승인 스냅샷:** `project_id, contract_id, task_id, action_type, tool_id, target, payload_digest, estimated_cost, risk_level, expires_at, approver_id, decision, decided_at`. 실행 시 digest·대상·범위가 바뀌면 **재승인**.

## 4. 서버 권한 평가 순서
1. 인증 주체·세션 유효성 확인.
2. 요청 프로젝트/자원 일치 및 RLS 멤버십·역할 확인.
3. 계약 활성/만료/중단·작업 배정·역할 capability 검증.
4. 도구 allowlist·위험 등급·대상 리소스·입력 스키마 검사.
5. 승인 스냅샷(필요 시) 및 유효기간/철회 여부 검사.
6. 예산 잔여액·예약/실사용/상한·요청 중복 멱등성 확인.
7. 실행 시작 직전 재검증, 상태 전이 및 감사 이벤트 기록.
8. 결과 검증·산출물 보존 후 사용자 수락 별도 처리.

**거부 응답 규칙:** 자원 존재 여부 노출을 피하기 위해 타 프로젝트 자원은 안전한 not-found 또는 forbidden 처리. UI는 권한 거부 사유를 설명하되 비밀 정보는 표시하지 않는다.

## 5. RLS/권한 테스트 연결 (격리 개발 DB에서만)

| ID | 테스트 | 기대 |
|---|---|---|
| AUTH-01 | outsider가 타 프로젝트/문서/실행 조회 | 거부 |
| AUTH-02 | viewer가 문서·업무·계약 수정 | 거부 |
| AUTH-03 | editor가 owner 대신 계약 활성화 | 거부 |
| AUTH-04 | editor/viewer가 타인 댓글 UPDATE/DELETE | 거부 |
| AUTH-05 | 멤버가 타인의 반응·알림 상태 변경 | 거부 |
| AUTH-06 | 외부 수신자 알림 생성/활동 위조 | 거부 |
| AUTH-07 | editor가 과거 문서 버전/AI 실행 상태 조작 | 거부 |
| AUTH-08 | 프로젝트 A의 계약/승인을 프로젝트 B 작업에 재사용 | 거부 |
| AUTH-09 | 계약 해지·권한 회수 후 도구 실행 | 거부 |
| AUTH-10 | 승인 만료/철회·요청 payload 변경 후 고위험 실행 | 거부 |
| AUTH-11 | 예산 초과/중복 실행 요청 | 실행 차단·중복 청구 없음 |
| AUTH-12 | `project_members` SELECT 정책 재귀 여부 | 오류 없이 허용 범위만 조회 |

**현 상태:** 이 표는 목표 정책과 테스트 계획. 기존 SQL의 실제 취약점은 개발 DB 재현 전까지 확정하지 않는다.

## 6. 제품 정책 미결정
- POL-01 editor에게 실행 계획/산출물 승인 위임 허용 여부 및 상한.
- POL-02 viewer 댓글·반응 기본 허용 여부.
- POL-03 R2 내부 변경의 자동 승인 예외 범위.
- POL-04 프로젝트 삭제·복원과 데이터 영구 삭제의 권한 분리.
- POL-05 서비스 운영자/지원 인력의 데이터 접근·감사/긴급 권한.
- POL-06 계약 종료 후 진행 중 작업 취소·정산 및 로그 보존 기간.

**임시 MVP 기본값:** owner 최종 승인, editor는 문서/업무 편집, viewer는 읽기만, AI는 계약 내 초안/도구 실행만. 확정 전 구현 정책으로 간주하지 않는다.
