# PlanOS 기획 진입 2경로 및 진행 중 AI 인력 투입 — 사용자 확정 방향 (2026-10-21)

## 핵심 결정
- 메인에서 기획을 시작하는 방식은 **① 직접 기획(기존 PlanOS 방식) / ② 기본 제공 PM 직원과 진행** 두 경로로 선택한다.
- **어느 경로를 택하든 동일한 프로젝트 진행 대시보드로 이어진다.**
- **직접 기획을 택한 사용자가 기획 진행 도중에도 AI 전문 직원을 투입할 수 있다.** 처음부터 AI Team을 선택하거나 프로젝트를 다시 만들 필요가 없다.
- PM 주도 경로에서도 사용자는 직접 문서·작업을 수정하고 필요한 범위에서 전문가를 투입할 수 있다.
- 기획 시작 경로는 **독점적인 서비스 모드나 접근 제한 플래그가 아니다.** 프로젝트, 문서, 작업, 상태, 승인/감사 이력은 같은 ID와 저장 체계를 공유한다.

## 사용자 여정
메인 → 프로젝트 만들기 → [직접 기획 | 기본 PM 직원 진행] → 공통 진행 대시보드 → 문서 작업/업무 처리 → 언제든 AI 직원 투입(역할, 작업, 소스, 계약·비용·권한 확인) → 승인된 범위에서 실행 → 보고서/수락 → 동일 대시보드에 결과 반영.

## 기능 수용 기준 (설계·추가 구현 대상으로 추적)
- E-01: 메인에서 두 시작 경로를 알기 쉽게 제시한다. 기존 직접 기획 기능·진입 동선은 보존한다.
- E-02: 생성한 프로젝트와 문서가 경로에 무관하게 하나의 `project_id`에 귀속된다.
- E-03: 직접 기획 도중, 이미 작성한 문서/업무를 그대로 이용해 AI 직원 요청을 시작할 수 있다. 새 프로젝트 생성이나 문서 복제는 요구하지 않는다.
- E-04: 기본 PM을 선택하더라도 사용자 수정, 사람 작업, 전문 AI 추가가 가능한 동일 대시보드로 이어진다.
- E-05: AI 직원의 계약 동의·제공사/데이터 범위·예산·실행·결과 수락은 각각 권한/승인 정책을 따른다. 직접 기획/PM 선택 자체는 유료 실행 동의가 아니다.
- E-06: 도중 AI 투입 시 해당 시점의 document ID/revision/digest와 업무 범위를 고정하고, 이후 수정 시 stale 승인·계약 재검토를 수행한다.
- E-07: AI 직원 투입을 하지 않고도 기존 PlanOS 직접 기획을 끝까지 진행할 수 있다.
- E-08: PM 기본 제공의 비용/무료 범위와 AI 전문 직원의 유료 가능 실행 조건은 확인되지 않은 상태로 단정하지 않는다. 실제 AI 호출/무과금 시뮬레이션/사람 작성 계획을 정확하게 구분해 표시한다.

## 기존 문서와의 정합성 수정 필요
1. PRD 'Solo Mode / AI Team Mode'는 **상호배타적 선택**으로 해석되지 않도록 설명 보완. 협업 기능은 프로젝트에 동적으로 추가되는 capability이며 직접 기획을 계속 유지한다.
2. SERVICE_PLAN 'Solo ↔ AI Team 모드 전환' 문구를 **두 가지 시작 경로 + 진행 중 동적 인력 배치**로 보강한다.
3. FUNCTIONAL_SPEC 신규 기능 추적: 메인 선택 / 공통 대시보드 / 진행 중 직원 요청 / 사용자 직접 개입·전환 / 기존 기능 회귀.
4. 화면/데이터 정책: 프로젝트 선택 경로 값이 저장되어도, 이는 진행 UX 기본값이지 AI 요청권 차단 조건이 아니다.
5. E2E: '직접 기획→PRD 작성→진행 대시보드→AI 전문 직원 투입→검수 결과'와 'PM 시작→직접 수정→AI 전문 직원 투입'을 각각 검증한다.

## 미결정(임의 확정 금지)
- 기본 PM 직원의 실제 AI 공급자·호출 빈도·무료/유료 범위와 기본 제공 조건.
- 시작 경로 변경 UI 표현, PM의 proactive 동작 수준, 최초 공개할 전문 역할의 종류/가격.
- 데이터베이스에 시작 경로를 저장할지, 프로필 선호로만 저장할지.
