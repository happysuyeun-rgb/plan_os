## 1. 총평과 개선 방향

PlanOS의 핵심 자산은 **기존 AI 인터뷰 → 프로젝트 산출물 → 직접 진행하거나 AI 직원 투입 → 지속 업무 관리/검수 → 재방문 시 맥락 유지**라는 연속성이다. 'AI 직원'은 고객이 프로젝트에서 맡길 일을 쉽게 고르는 인터페이스이며, 수익 가치의 본체는 실제 업무 완료·재작업 감소·지속 관리다.

기존 v2.0에 이미 명시된 것은 **다시 발명하지 않는다**:
- 기존 PlanOS의 AI 기획을 유지하고 진행 도중 언제든 직원 투입.
- 직무/소통성향(F/T)/리딩 방식/경력/모델/계약/권한을 각각 별도 차원으로 분리.
- 채용은 실제 사람 고용이 아닌 범위가 제한된 서비스 계약.
- PM은 명시적으로 배정된 1개 또는 복수 프로젝트만 관리.
- 고객의 **경력 적립**과 **외부 공개**·후기·원본·마케팅 목적 동의 분리(기본 미허용).
- 경력활동일, 사람 수락, 역량검증을 분리; 모델이 경험을 통해 자체 학습한다고 주장하지 않음.
- 사용자 승인, 데이터/비용 제한, 비밀 프로젝트 보호; 기존 계약 승급 후 가격 자동 상승 금지.

**추가로 개선해야 할 지점은 고객이 지불할 차이, 경력/능력과 가격의 인과관계, 첫 구매까지의 마찰, 좁은 첫 성공 경험, 반복매출 실증이다.**

## 3. 상세 개선안

### IMP-01. 기본 AI와 정식 PM 사이에 구매 가능한 결과 차이를 만든다 — P0

**문제:** '기본 AI도 계획을 세우는데 왜 PM 채용에 돈을 내는가?'에 대한 고객 관점 답이 아직 충분히 구체적이지 않다.

**제안:**
- **기본 AI 기획:** 사용자가 현재 프로젝트에서 질문하면 인터뷰·문서 생성/수정·코칭/다음 단계 제안. 지속 점검·예정 시간에 알아서 실행할 권한이나 백그라운드 성능을 기본 약속하지 않음.
- **정식 채용 PM:** 명시된 담당 프로젝트의 현재 작업/차단/최근 변경/검수 대기 상태를 읽고, **실제로 실행된 작업 로그를 근거로** 마일스톤·우선순위·승인 대기·필요 직원을 관리. 프로젝트 간 조회는 승인된 범위 한정.
- **최소 유료 가치 계약:** (a) 현재 상태 브리핑, (b) 완료 기준이 있는 다음 업무 제안, (c) 승인 요청 목록, (d) 진행/차단 사유 기록, (e) 과거 브리핑 대비 무엇이 달라졌는지.
- **지속 수행 약속은 실제 scheduler/worker가 존재하고 실측으로 확인된 경우만 표기**. 기술 미완료 동안의 PM mock/수동 호출은 그대로 고지.
- PM이 **스스로 승인하거나 고객을 대신해 새 직원 결제·배포·원문 공개를 하지 않는** 권한 원칙을 유지.

**수용 기준:** 신규 사용자 5명에게 두 상품의 샘플을 보여주고 '왜 유료 PM을 선택하는지'를 자신의 말로 설명할 수 있는지 확인; 실적 지표는 PM 제안→사람 승인→실제 결과 수락과 관리 시간의 전후 비교.

### IMP-02. '1프로젝트 PM 운영 루프'를 첫 제품 품질 기준으로 잡는다 — P0

**제안한 단일 수직 루프:** 기존 AI 인터뷰/기획 KEEP → 현재 프로젝트에서 PM 호출/선택 → 최신 업무·문서 브리핑 → PM이 구체 업무 1건과 완료기준 제안 → 프로젝트 owner 승인 → 전문 QA 또는 기획검수 직원이 제한 범위 실행 → 증거 있는 결과 보고 → owner 수락·수정요청 → 다음 방문 시 동일 문서·업무·상태 복원.

- G1 저장/복원·RLS 보호 및 S1~S7 서버 실행/권한 검증은 생략 불가.
- 기술적 복수 프로젝트 지원을 설계하더라도 **첫 고객의 실행 품질은 1프로젝트로 먼저 검증**, PM 복수 프로젝트는 위 루프를 통과한 뒤 E2E 범위 확대.
- mock 직원 탐색/성향 선택을 개발해도 실제 채용/실행 성공률로 세지 않음.

**수용 기준:** 승인 없는 실제 작업 0, 타 프로젝트 접근 0, 브라우저 종료/복귀 시 데이터·실행 상태 보존, 최소 1개 실험 업무에서 근거 보고서와 실제 고객 수락/반려 증거 확보(합성자료 내부테스트와 외부 파일럿 단계 구분).

### IMP-03. 사업 MVP의 필수/가치시연/후속 범위를 분리한다 — P0

| 구분 | 첫 가치 검증에서의 취급 | 판정 이유 |
|---|---|---|
| 기존 AI 인터뷰·문서 생성·채팅·버전·복원 | **KEEP/P0** | 고객의 기존 시작 경험·전환 자산 |
| 프로젝트 진행 허브·업무/상태 | **MVP/P0** | PM의 업무 입력·결과 증거 |
| AI PM 1종·성향 2개 시연 | **MVP/P0** | 채용 선택 이유 시험 |
| 문서 교차검수 전문 업무 1종 | **MVP/P0** | 첫 검증 가능한 실행·과금 후보 |
| 프로젝트별 계약·비용·권한·승인 | **MVP/P0** | 외부 호출 및 고객 정보 보호 |
| PM 복수 프로젝트 1~3개 | **Mock 우선 → 품질 통과 후 실제 확대** | 핵심 장기 가치지만 추가 권한/스케줄러 비용 |
| 경력 적립/공개·철회 의사 선택 | **UX/정책/데이터 기반 먼저** | 고객 권리 보호, 완료 로그 연결 |
| 경력 승급/랭킹·등급별 유료 가격 | **후속** | 실제 작업·차등 품질·표본 필요 |
| 전직무 에이전트·모든 모델/툴 패키지 | **후속** | 개발 비용과 정합성 확장 |

**주의:** 이 표는 첫 실고객/매출 검증의 범위 조정안이지 v2.0에서 중요하게 결정한 PM 복수 프로젝트와 경력 시스템을 제품 비전에서 제거하자는 제안이 아니다.

### IMP-04. AI 직원 가격을 경력 '연차'보다 검증된 전문 성과에 연결 — P0

- **경력 사실:** 고객이 적립 허용한 실제 활동일수, 수락 프로젝트/산출물, 고용주 평가, 검증 업무 종류와 표본.
- **능력 사실:** 같은 과업세트에서의 성공/실패, 근거 일치, 심각 결함 탐지·오탐, 품질검토 시간, 모델/도구 호환성과 평가일.
- UI는 '경력 등급'과 '직무 역량 검증'을 별개로 표기. 경력 180일 = 모델이 학습해 능력이 높아졌다는 표현 금지.
- **같은 직무·같은 모델·같은 도구/계약 범위**에서 초급보다 중급/고급 직원의 검수 품질·감독 부담이 실제로 차이가 나는지 실측할 것.
- 경력이 많아도 품질 개선이 없다면 높은 고용료는 정당화되기 어려우므로, **등급별 가격 차등은 연구 가설로 유지**. 계약 단가 동결과 고객 공개 동의 무강제 원칙 유지.
- 동일 지표에서도 업무 난도·검수자 편차·표본수 차이를 통제. 고객의 호감도 점수만으로 전문 역량 인증 금지.

**수용 기준:** 정답/실패가 기록된 합성 과업 최소 5세트를 사람이 판정하고 모델/도구·직무별 결과 표를 작성한 후 등급 가격 실험; 수치와 실제 가격은 실측 이전 미확정.

### IMP-05. 채용 UX는 간단하게, 필수 승인은 정확하게 — P1

**고객 눈에 보이는 4단계 제안:**
1. 직원 선택 — 직무/성향/검증성과/모델/예상 금액을 비교.
2. 배정 범위 — 단발/전담/정식 PM, 대상 프로젝트·도구·기간 선택(복수 프로젝트 기본 자동선택 OFF).
3. 계약 검토 — 실제 제공사·전송 문서·계획/실행 상한·취소 조건/필요 필수 동의를 검토.
4. 업무 시작 — 계획/실행의 **별도 승인 이벤트**는 위험 정도에 따라 명확하게 표현하고 결과는 사람이 별도 수락.

- **경력 적립**·사례 공개(공개/익명/비공개)·후기/로고/마케팅/모델 학습 동의는 각각 별도 선택으로 보존; 기본 미허용.
- 목적별 동의는 필요 시 계약 중 표면화하되 '4단계'는 화면 그룹핑이지 동의를 숨기거나 통합 승인한다는 뜻이 아님.
- 선택/견적/계약 입력 중 로그인 만료·예산 변동·문서 revision 변경 후 사용자가 처음부터 재입력하지 않도록 안전한 초안 복구 설계 검토.
- 회사 고객이 문서의 공개/전송 권한을 갖지 않는 경우 고용 자체와 데이터 공개 권한을 분리.

**수용 기준:** 5명 사용성 테스트에서 최소 4명이 독립적으로 업무를 요청하고, 실제 승인한 문서·공급자·상한과 경력 공개 범위를 올바르게 설명할 수 있는지 확인.

### IMP-06. 프로젝트 진행 도중 직원 투입·교체를 서비스의 중심 행동으로 — P1

- '직접 진행' = 기존 AI 인터뷰·기획서 생성 및 채팅 수정 가능. **AI 없음/사람 수동 작업 only가 아님**.
- 진행 대시보드에서 현재 문서·업무/완료기준/오류·승인 대기를 보존한 채 직무 직원 추가·교체.
- 직원 교체: 이전 계약/실행·결과·수락 기록 불변, 열람 가능한 최소 최신 컨텍스트만 새 직원에게 새 범위로 인계, 미승인 외부 데이터 이전 금지.
- 실제 작업 중 해임 시 신규 실행 차단→진행 중 업무의 취소/정산/문서 변경 충돌 처리→새 계약 검토.
- 처음부터 PM 채용을 강제하지 않으며, 사용자는 언제든 AI 인터뷰/문서 채팅으로 직접 재진입.

**수용 기준:** 기존 프로젝트에서 AI 직원 투입/교체 전후 프로젝트 ID·문서 revision·업무/검수 이력·고객 편집 내용이 그대로 남고, 공급자 재동의·프로젝트 접근 분리 테스트 통과.

### IMP-07. 단발 매출과 PM 반복매출의 실험을 분리 — P1

**검증 상품 A:** 기획 정합성 검수 1회(문서 2개 이상 → 누락·충돌·검증불가와 근거·개선 체크리스트). 독립 업무의 품질과 실제 지불을 관찰.

**검증 상품 B:** 정식 채용 PM 관리(승인된 1개 또는 명시된 복수 프로젝트의 진척·차단·승인 대기·업무 조율). 주간/월간 갱신 필요성과 실제 관리 부담 감소 확인.

상품별 분리해야 하는 숫자: 예상가/실판매가, 수락 산출물당 모델+도구+재시도+지원/인간QA+호스팅 변동원가, 고객획득비, 재구매·갱신률, 실제 실행 실패/분쟁·환불비용.
- **무료/기본 AI 기획**은 기존 모델 호출 원가가 발생할 수 있으므로 '무제한 무료' 가정 금지.
- **정식 PM 기간 과금**은 스케줄러/worker가 실제 실행되지 않는 동안 '자동 상시 근무'로 판매 금지.
- 등급별 단가와 모델·툴의 공급자 원가는 독립 항목. 같은 계약에서 등급 승급 시 가격 인상 금지.
- 가격 숫자(단건/정기/등급배수)는 사용자 구매 실험·원가 측정 전 확정 금지.

**사업상 중단 기준:** PM 유지 사용률은 있어도 반복 방문·업무 수락·관리시간 절감이 없다면 월 구독 상품성 재평가; 단발 검수가 범용 AI 대비 우월성이 없다면 포지셔닝/사용 채널 재검토.

### IMP-08. 경력 적립 미동의 고객을 불리하게 만들지 않는 역량 평가 — P1

- 고객의 거절/비공개를 그대로 존중. 비공개 고객의 프로젝트 기록/소스/원문을 **무단으로 공통 학습·역량 벤치마크·마케팅 자료에 사용하지 않는다**.
- AI 직원 역량은 고객별 경력 적립과 별도로 **독립적인 합성 테스트셋**, 저작권·사용권 확보된 공개 평가 과제로 측정 가능.
- 그러한 테스트 결과는 직원의 '검증 역량' 배지로 분리. 고객 경력 일수 또는 고객 프로젝트 수처럼 표기하면 안 됨.
- 평가 과업의 정답과 평가일/모델 버전/한계를 함께 보여 주고 모델 변경 시 재평가.

**수용 기준:** 경력 적립 OFF라도 계약대로 업무 실행 가능, 외부 경력 공개 0, 직원 능력 검증 자료는 고객 비밀과 별도 provenance.

### IMP-09. 'AI 직원 성과표'는 진실한 분모가 있는 경우에만 — P2

**고객에게 표시할 가치 후보:** 맡은 작업 수, 사람 수락된 작업/수락률, 수정 요청/재작업, 중도 실패·취소, 해당 직무 평가 과제, 실제 검증 활동일, 고객 후기 표본.

**필수 한계:** 성공률은 시험과제 합격률/기계 실행 성공률/사람 결과 수락률을 섞지 않음. 쉬운 업무만 골라 수행한 직원과 어려운 업무를 맡은 직원의 숫자를 동일 평점으로 순위화하지 않음. 표본 부족/측정 기간/검증 시점/업무 난이도 표시. 평가·프로젝트 공개 동의 철회 및 캐시 갱신 반영. **가상 데모 숫자를 실적이라고 표기하지 않음.**

**수용 기준:** 공개된 모든 성과 지표에 server evidence ref, 정의된 분자/분모, 기간·모델·직무·표본, 공개 허용 범위가 있어야 함.

## 7. 최종 권고·결정 대기

**유지할 비전:** AI 기획을 유지하고 원하는 순간에 AI 직원을 채용·투입하며, 실제로 프로젝트를 진행·검수하고, 고객 허락이 있을 때만 검증된 경력/평가를 축적하는 플랫폼.

**지금 가장 우선할 제품적 증명:** “PM이 프로젝트 상태를 이해하고 전문 직원 1건을 제안·수행·검수·수락까지 연결한다.”

**지금 가장 우선할 사업적 증명:** “고객이 다음 달에도 이 PM을 고용할 만큼 시간을 절약하거나 업무 결과가 좋아지는가.”

**최종 승인 전 미결정:** 무료량·가격/수익배분·등급 승급 임계, 실제 모델 공급자·권한/데이터 보존/국외이전, 자동 PM 스케줄, 직원 성능 평가, 외부 공개/후기/철회/법률 권리, 운영 마이그레이션·배포·결제/환불.

**작업 제한:** 이 문서 작성으로 위 문제를 해결·검증·승인한 것으로 처리하지 않는다. 독립 제안서이며 원본 제품 문서를 변경하지 않는다.
