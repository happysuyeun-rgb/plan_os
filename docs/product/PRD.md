# PlanOS 3.0 × AI 인력사무소 — 통합 서비스 기획서 (PRD)

**최초 작성일:** 2026-10-16  
**최종 수정일:** 2026-10-19  
**문서 버전:** v0.3  
**진행 상태:** 제품 정의 초안(정합성 감사 보완) / 리뷰·승인 전  
**문서 책임:** 제품 기획 기준 문서(초안)  
**기준:** 기존 PlanOS 기능 유지 + AI 인력사무소 단계적 통합

> **핵심 메시지:** 혼자 시작해도, 혼자 일할 필요는 없으니까.
>
> **제품 약속:** AI 직원을 '고용한 듯 보이는' 대화가 아니라, 권한·예산·검증·승인 경계 안에서 실제 작업을 수행하고 증빙을 남기는 협업 경험을 제공한다.
>
> 이 문서는 **TARGET(목표)** 제품 정의다. 현재 구현(CURRENT)이나 운영 검증 완료를 뜻하지 않는다. 기존 `docs/TECH_SPEC.md`는 구 PlanOS V1의 구현 참조 자료로 보존하며, 신규 제품의 범위는 이 PRD를 우선한다. 단, 기존 구현 호환성과 실제 기술 가능성은 별도 검증해야 한다.

## 1. 문제 정의와 시장 가설

### 1.1 핵심 문제
1. 1인 창업자·프리랜서는 프로젝트를 기획·개발·마케팅·검증하는 데 여러 도구와 외주를 오가며, 결과물과 의사결정 맥락이 흩어진다.
2. 일반 AI 채팅은 제안은 빠르지만 장기 작업 상태, 도구 실행, 결과 검증, 승인, 비용 통제가 끊기기 쉽다.
3. 외주 의뢰는 요구사항 작성·견적 비교·업무 분담·성과 확인 부담이 크다.
4. AI 에이전트 서비스는 '실행됨'과 '검증됨'을 혼동하기 쉬우며 사용자에게 불확실한 성과를 과장할 위험이 있다.

### 1.2 가설(아직 검증되지 않음)
- H1: 단일 프로젝트 공간에서 사람의 작업과 AI의 작업을 연결하면 산출물 완성까지의 시간이 단축된다.
- H2: 역할/기술/권한이 명확한 AI 인력을 고르는 흐름은 빈 채팅창보다 시작 장벽을 낮춘다.
- H3: 실행 증빙과 사람 승인 절차가 재이용 의향을 높인다.
- H4: 단순 생성량보다 **검증된 작업 완료율**이 제품 가치와 비용 효율을 더 잘 설명한다.

### 1.3 1차 타깃
- **핵심:** 혼자 제품/웹사이트/콘텐츠를 만드는 1인 창업자, 비개발자 창업 준비자, 프리랜서.
- **확장:** 2~5명 규모 소규모 팀, 초기 에이전시.
- **MVP 제외:** 대기업 전사 ERP, 실제 근로계약·인력 파견, 법률/의료/투자 자동 결정, 무감독 자율 결제·운영 배포.

## 2. 포지셔닝과 제품 원칙

**포지셔닝:** 프로젝트 운영 워크스페이스(PlanOS) + 실제 도구 작업을 수행하는 AI 팀 + AI 역할 탐색/계약 경험(인력사무소).

- **Solo Mode:** 사람 혼자 작업·문서·업무·히스토리를 관리.
- **AI Team Mode:** 동일 프로젝트 데이터에 승인된 AI 역할을 붙여 작업을 위임.
- **연속성:** 모드 전환 시 프로젝트·문서·작업·이력이 유지된다. 서로 다른 제품이나 별도 데이터 사일로를 만들지 않는다.
- **진실성:** AI의 프로필/경력은 실제 인간의 학력·재직 이력처럼 꾸미지 않는다. 모델, 제공 도구, 검증된 수행 능력, 제약, 테스트 결과를 구분한다.
- **실행 우선:** 대화 출력만으로 '업무 완료' 처리하지 않는다. 실제 산출물과 검증 기록이 있어야 완료 후보가 된다.
- **사람의 통제:** 대외 발송·배포·결제·삭제·외부 공유 등 영향 큰 행위는 기본적으로 사전 승인.
- **비용 통제:** 실행 전 추정 비용/상한, 실행 중 사용량, 완료 후 실제 비용을 확인할 수 있어야 한다.

└─ 대시보드
   ├─ 프로젝트 목록 / 새 프로젝트 / 휴지통(기존)
   ├─ 프로젝트 워크스페이스
   │  ├─ 개요·목표·브리프

   │  ├─ AI 팀(계약·역할·권한)
   │  ├─ 실행 내역(도구·증빙·오류·재시도)
   │  ├─ 승인함 / 비용
   │  └─ 활동·댓글·알림
   ├─ AI 인력사무소
   │  ├─ 역할 탐색·검색
   │  ├─ 역할 프로필·검증 정보
   │  ├─ 업무 적합성 질문(면담)
   │  └─ 서비스 계약 → 프로젝트 킥오프

**호환성:** 기존 `/projects/:projectId` 및 `/projects/:projectId/:docType` 문서 딥링크 유지. 신규 워크스페이스의 최종 URL은 IA 설계에서 결정하며, 기존 URL을 임의로 다른 화면으로 치환하지 않는다.

## 5. MVP 사용자 여정 — 한 번의 실제 실행

1. 사용자가 프로젝트를 생성하거나 기존 프로젝트를 선택한다.
2. 프로젝트 목표/제약/예산을 입력하고 AI 인력사무소에서 역할을 찾는다.
3. 프로필의 **실제 사용 가능 도구·검증 수준·모델 제한·예상 비용**을 확인하고 간단한 업무 적합성 질문을 진행한다.
4. 사용자는 고용계약이 아닌 **AI 서비스 이용 범위/권한/예산 계약**에 동의하고 프로젝트에 역할을 배치한다.
5. AI PM이 목표를 작업으로 분해한다. 사용자는 계획을 검토·수정·승인한다.
6. 승인된 전문 AI가 서버 측 도구로 한 가지 실작업을 수행한다.
7. 시스템이 산출물·검증 결과·출처/도구 실행 로그·비용을 기록한다.
8. AI PM이 사실 기반 브리핑을 작성하고, 사용자가 산출물을 수락·수정 요청·반려한다.
9. 상태·비용·다음 작업이 프로젝트 공간에 남고, 사용자는 Solo/AI Team Mode를 전환할 수 있다.

**MVP E2E 성공 기준:** PM + 전문 AI 1개 역할로 위 여정이 끝까지 동작하고, 브라우저 종료 후에도 작업 상태/증빙이 남으며, 사용자가 산출물을 확인·수락할 수 있다.

### 6.1 역할 정의(MVP)
- **AI PM:** 브리프 구조화, 계획 수립, 승인 요청, 작업 위임, 결과 검토, 사실 기반 보고. 사용자를 대신해 무제한 자율 결정하지 않음.
- **전문 AI 1명:** 초기에는 범위를 좁힌 문서/리서치/기획 산출물 작업 중 한 가지로 선택. 실제 실행 가능한 도구·검증 절차를 확보한 작업만 공개.
- **추가 역할:** 첫 E2E 검증 후 확장. 화면상 인원 수만 늘리는 방식 금지.

### 6.2 업무 상태와 계약 상태
- 업무: `draft → planned → awaiting_approval → queued → running → verifying → awaiting_acceptance → accepted`.
- 예외: `blocked / failed / cancelled / rejected / needs_revision`. 각 전이는 서버 권한과 멱등성 검증 대상.
- 서비스 계약: `draft → accepted → active → suspended/expired/terminated`. 계약 종료 시 신규 실행 중단, 진행 중 작업의 취소·정산·증빙 보존 규칙 적용.
- **정확한 DB enum·전이표는 Phase 1 설계에서 확정.** 본 문서의 상태는 제품 요구 수준의 제안.

## 7. 정책과 안전장치

### 7.1 승인
- **기본 승인 필요:** 코드 병합/배포, 데이터 영구 삭제, 외부 메시지 발송, 비용 결제, 고객 데이터 외부 공유, 권한 상승.
- 승인 화면은 실행 내용·대상·비용·취소 가능성·예상 영향·유효기간을 보여준다.
- 거부/만료 시 실행하지 않는다. 승인한 행위 외 범위로 도구를 확장하지 않는다.

### 7.2 권한과 개인정보
- 프로젝트 접근권한과 AI 작업권한은 별도로 관리한다. UI 숨김만으로 권한 제어하지 않는다.
- 모델·도구 호출 전 서버가 사용자/프로젝트/역할/계약/예산을 검증한다.
- 민감 정보는 최소 전송; 로그 비밀 마스킹, 보존/삭제/내보내기 정책 마련.
- 외부 공급자 장애·약관 변경 시 자동 대체는 capability/데이터 처리 조건이 동등할 때만 허용.

### 7.3 비용·요금
- **수익모델 가설:** 개인 기본 구독 + AI 실행 사용량/크레딧 또는 상위 플랜. 실제 가격·무료 제공량·원가율은 미확정.
- 모델 토큰 비용 외 워커/저장/도구/API/재시도 비용을 포함한 단위경제 측정.
- 비용 표시 시 **예상**과 **확정**을 구분하고, 실패/취소/재실행 환불·정산 규칙을 마련.
- FreeLLMAPI는 **내부 비식별 실험 후보**이며 고객용 상용 엔진이나 무료 무제한 약속의 근거가 아니다.

| 호환성 | 기존 PlanOS 로그인·문서·버전·내보내기·댓글·휴지통 회귀 통과 |
| 접근성 | 키보드 조작, 상태·오류의 텍스트 안내, 반응형 핵심 경로 |
| 품질 | 생성 성공률과 검증 통과율 구분; AI가 '완료'라고 말해도 검증 전에는 미완료 |

## 9. 측정 지표와 파일럿 수용 기준

**North Star(제안):** 주간 사용자 승인 완료된 **검증 가능 AI 작업 수**(작업 증빙 링크·승인 기록 필요).

- 활성화: 가입 후 첫 프로젝트 생성률, 첫 AI 역할 배치율, 첫 승인된 작업 완료율.
- 실행: 작업 시작→검증 완료율, 수락률, 재작업률, 실패/재시도율, 중앙값 소요 시간.
- 비용: 승인된 작업 1건당 총원가, 예산 초과 시도 차단율, 비용 예측 오차.
- 신뢰: 승인 없는 고위험 실행 **0건**, 교차 테넌트 노출 **0건**, 근거 없는 완료 보고 **0건**.
- 파일럿: 소수 실제 사용자와 최소 1개 반복 업무를 관찰. **숫자 목표치는 베이스라인 측정 후 확정**, 임의의 시장 검증 성과를 선언하지 않는다.

## 10. 범위 및 릴리스 단계

| 단계 | 범위 | 출시/완료 게이트 |
|---|---|---|
| Phase 0 | 기존 코드·CI·DB/RLS·회귀 감사 | build/lint 성공 + 핵심 회귀 검증 + RLS 위험 재현/차단 계획 |

| Phase 3 | 서버 AI 워커·도구·예산·승인 | 실제 1개 작업 완료·실패/취소·증빙 검증 |
| Phase 4 | AI PM 계획·위임·검증·브리핑 | PM + 전문 역할 1명 E2E |

## 11. 기존 자산과 재사용 전략

- **KEEP:** 프로젝트·문서·버전·댓글·히스토리·내보내기·휴지통 기능과 기존 사용자 URL(검증 조건부).
- **WRAP/MODIFY:** 현재 생성/채팅 인터페이스, 업무 데이터, 권한 정책, 대시보드, 활동/알림.
- **NEW:** 서버 작업 큐/워커, ModelGateway, 도구 실행·승인·비용·검증 엔진, AI 역할 카탈로그/계약/킥오프.
- **주의:** 기존 `src/lib/api/generation.ts` 및 `chat.ts`의 플레이스홀더 동작을 실제 AI 실행으로 간주하지 않는다. `generation_runs` 테이블만으로 durable worker가 구현된 것은 아니다.
- 기존 `docs/TECH_SPEC.md`의 V1 기술·화면 참조는 보존하며, 이 PRD가 V1의 구현 완료를 소급해서 주장하지 않는다.

## 13. MVP 범위 동결·제품 검증 게이트 (교차감사 보완)
- **최초 전문 AI 업무(D-01 사용자 승인 대기):** [2026-10-19 업무 선정·수용 기준 설계안](FIRST_SPECIALIST_AI_MVP_2026-10-19.md)에서 3개 후보를 비교해, 프로젝트의 기존 문서를 읽고 *요구사항 누락·중복·상충·검증 기준*을 분석한 **근거 있는 비공개 보고서** 1종을 1순위로 권고했다. 설계/QA 시나리오만 작성됐으며 실행/고객 검증/정책 확정은 남음. AI PM의 계획 수립과 전문 역할의 실행·검증 책임이 중복되지 않도록 별도 지정한다.
- **최소 실증:** PM 1명 + 전문 AI 1명 + 허용 도구 1종 + 프로젝트 1개. 입력→계획 승인→서버 실행→근거/산출물 기록→자동 검증→사용자 수락/수정까지 재접속 후에도 재현 가능해야 한다.
- **측정 대기:** 고객 검증 인터뷰, 기존 작업 시간/원가 기준선, 첫 작업 성공/수락률, 무료 체험·과금·실패 환불 정책이 미정이므로 수치형 KPI 목표를 임의로 약속하지 않는다.
- **출시 차단:** RLS 테스트, 기존 문서 자동저장·버전·복원 회귀, 동시 예산 예약/중복 호출 테스트, 도구 승인/만료/취소/개인정보 처리, 장애 중단/재개·지원 절차가 통과되지 않으면 공개 출시 금지.
- **추적:** [문서 품질 감사](../quality/DOCUMENT_REVIEW_2026-10-16.md) DQ-01~15를 해결 상태로 관리한다.

### 2026-10-19 감사 보정 — 모델 계획 비용/역할 공개 시점
- **실행 순서:** 프로젝트 문서/목표 사전 선택(모델 호출 없음) → owner의 역할·문서·외부 데이터 처리·계획 생성 예산 조건 계약 동의 → 유료 PM 계획 job(계약/한도 내) → 계획 버전 별도 승인 → 전문 AI 서버 실행 → 근거 검사 → 사용자 수락. 최초 전문 AI 설계안과 [P1-2 정책](MVP_CONTRACT_APPROVAL_COST_POLICY_2026-10-19.md) 기준.
- **기술 실증 vs 고객용 MVP:** Phase 2~3에 내부 최소 역할/계약/영속 실행, Phase 5에 역할 탐색·면담·계약 UX를 공개한다. 전체 고객 여정 E2E 성공 전에는 정식 MVP 완료가 아니다.
- **D-02/03/05/07:** 고객 가격·무료 체험·R0/R1 실행 허용·공급자 약관/데이터 보존이 **모두 미승인**. 서버 계획 생성 비용도 계약 예산에 포함되어야 한다. 검증 리포트 자동 PASS와 최종 사람 수락은 별도.
- **공식 누락 대장:** [Phase 1 교차 감사](../quality/PHASE1_CROSS_AUDIT_2026-10-19.md) AUD-01~12. 실제 비용/모델 처리·RLS/UX/오탐 fixture는 검증 전.
