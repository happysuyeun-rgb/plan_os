## 공통 표기 및 수용 기준
- 모든 TF는 **진입 조건 → 사용자/시스템 행동 → 산출 상태 → 실패/복구 → 권한·비용**을 포함한다.
- **주체**는 사용자, AI PM, 전문 AI, 서버 워커로 구분한다. 서버의 실행 성공과 사용자 수락은 별도 상태다.
- 사용자 역할: owner(소유자), editor(편집자), viewer(열람자), outsider(외부인). 상세 권한 매트릭스는 후속 정책/DB 설계에서 확정한다.
- **P0 핵심 경로:** TF-03 → TF-07~08 → TF-10~14 → TF-16~24 → TF-27. 첫 릴리스는 PM+전문 AI 1명으로 E2E 검증.
- **P0 호환 경로:** TF-04, TF-25, TF-29. 기존 문서·버전·휴지통 기능은 회귀 통과 필수.
- P1/P2 기능은 상세 UI 확정 전이라도 흐름 누락을 막기 위해 기록한다. 모든 화면의 출시가 확정됐다는 뜻은 아니다.

## 상세 실행 규칙: P0 핵심 경로

### 계약/배치 (TF-10~12)
1. 서버가 계약 요청자의 프로젝트 소유권과 선택한 역할의 사용 가능 도구를 검사한다.
2. 계약 화면은 **서비스 제공 범위**, 데이터 접근, 승인 필요 작업, 작업/프로젝트 예산 상한, 취소·정산 규칙을 분리 표시한다.
3. 사용자 수락 시 조건 스냅샷과 승인 시각·주체를 기록한다. 계약이 활성화되지 않으면 AI 배치를 허용하지 않는다.
4. 중복 제출은 멱등성 키로 하나의 계약만 만든다.

### 계획/실행 (TF-13~20)
1. PM 계획에는 작업 입력, 산출물 형태, 성공/실패 판정, 의존성, 예상 비용, 도구가 포함된다.
2. 승인 전에는 작업을 queued/running으로 전이하지 않는다.
3. 워커는 계약·역할·권한·예산·도구 allowlist를 실행 직전에 **서버에서 다시 검사**한다.
4. `queued → running → verifying`과 실패/취소 상태는 영속 저장하고, trace ID로 이벤트를 연결한다.
5. 사용자 브라우저가 닫혀도 서버 작업은 지속되며, 중복 재시도로 외부 효과/과금이 반복되지 않아야 한다.

### 검증/수락 (TF-21~24)
1. 검증기는 도구 호출의 성공과 산출물 품질을 별도 기록한다. 검증 실패는 accepted가 아니다.
2. PM은 근거 없는 완료 표현을 금지하고 미검증/부분 완료를 명시한다.
3. 사용자 수락 시 산출물 버전·검증 증빙·비용·수락 주체를 묶어 기록한다.
4. 수정 요청은 원 작업의 새 revision으로 연결하고, 무단 반복 실행은 금지한다.
5. 취소 요청 시 실행 중 도구가 즉시 취소 불가능하면 그 사실과 후속 정산 상태를 표시한다.

### 2026-10-19 첫 전문 AI 흐름 정합성 보정 (설계만)
- 첫 기술 실증의 TF-07~09(고객용 역할 탐색·면담) 화면은 Phase 5 공개 대상. Phase 2~3에서는 owner 동의한 **내부 최소 역할/계약**으로 TF-10~14/16~24의 서버 E2E를 우선 실증한다. Phase 5 완료 전 정식 고객 여정 완료 아님.
- **비모델 사전 선택 → TF-10/11 계약·데이터/계획비용 예산 동의 → TF-13 PM 계획(모델 호출시 서버 job+별도 비용 예약) → TF-14 계획 버전 승인 → TF-16~21 실행/자동검증 → TF-22~23 브리핑/수락** 순서 고정. 계약 전 비용 발생 AI 계획 호출 차단.
- TF-21은 입력 digest·schema·인용문 **존재/범위 검사**만 기계 검증한다. 의미 품질은 reviewer/human, 사용자 수락은 TF-23 이벤트이며 자동 PASS와 동등하지 않음.
- 공급자 원가가 작업 실패/반려에도 발생할 수 있으므로, TF-27 비용 관측/정산은 TF-23 수락과 별도로 수행. [첫 AI 설계안](FIRST_SPECIALIST_AI_MVP_2026-10-19.md) / [P1-2 정책](MVP_CONTRACT_APPROVAL_COST_POLICY_2026-10-19.md) / [교차감사](../quality/PHASE1_CROSS_AUDIT_2026-10-19.md).
