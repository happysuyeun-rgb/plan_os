# PlanOS 3.0 × AI 인력사무소 — 통합 서비스 운영정책 v1.0

**작성:** 2026-10-20 · **상태:** MVP 구현·내부 테스트에 쓰는 운영 규칙 기준안. 가격/보존 기간/법적 동의/외부 모델·운영 배포는 검토·승인 전. 고객용 법적 약관 또는 개인정보 처리방침으로 바로 게시하지 않는다.

## 1. 정책 기본 원칙과 범위
1. 사람에게 서비스로 제공되는 것은 AI 소프트웨어 실행 기능이며, 실제 인력 고용/인력 파견이 아니다.
2. 사용자에게 약속하는 결과는 '근거와 검수 경로가 있는 산출물'이지 결함 없는 완벽한 결과가 아니다.
3. 기본 거부(default deny) + 최소 권한 + 사전 동의/비용 통제 + 실제 증거 기반 상태 보고.
4. 상용 정책 미확정은 임의의 무제한·무료·즉시 삭제·전액 환불 약속으로 대체하지 않는다.
5. 운영 DB/외부 AI 전송·과금/배포는 승인된 시점 전까지 제한.

## 1.1 AI 직원 실경력·공개·등급·가격 정책 보정안 (2026-10-21)

> [고객 동의·실경력 축적·승급·가격 정책](AI_STAFF_VERIFIED_EXPERIENCE_CONSENT_TIER_PRICING_2026-10-21.md)에 채용 시·프로젝트 종료 시 별도 동의 UX, 검증된 경력일수 계산, 후기·등급 승급, 초급 저가 채용을 정의함. **실제 고객용 약관/가격표/개인정보 고지로 출시 확정한 내용은 아님**.

- **실행 계약과 경력 사용은 별개:** 프로젝트 경력 적립 허용·공개(실명/익명/비공개)·집계 점수 공개·포트폴리오/마케팅/후기 공개·모델 학습은 목적별 별도 동의. 기본 거부·미동의 고객에게 불이익 금지.
- **철회:** 공개 범위 축소/철회는 플랫폼 공개 내용 제거·업데이트, 경력 적립 철회는 직원 등급 계산 재평가. 경력/홍보 사용을 위한 내부 작업 로그의 무단 전용 금지.
- **검증 기준:** 초급·중급·고급은 AI의 인간 이력을 위장하는 연차가 아니라 실제 고객이 승인한 직원 수행일수/업무 수락·검수·평가의 증빙 기반. 같은 날 복수 프로젝트라도 일수 1일.
- **가격 원칙:** 같은 직무·모델 패키지·계약 조건이면 초급 단가를 낮게 책정하는 정책을 개발한다. 승급 후에도 진행 중인 계약 가격은 자동 변경되지 않으며 갱신 때 사용자 재동의 필요.
- **보안:** 고객의 원문·코드·디자인·대화·개인정보를 다른 고객/다른 공급자 모델로 경력 데이터라며 재전송하지 않는다. 데이터/사업자 표시 및 유료 가격·개인정보 권리 검토는 서비스 공개 전 실시.

## 2. 회원·프로젝트 권한
| 사용자 | 프로젝트/문서 | 사람 업무 | AI 계약/실행/최종 승인 | 비공개 AI 결과·원가 |
|---|---|---|---|---|
| owner | 전체 소유 범위 | 읽기/쓰기 | 허용(유효 계약·예산·동의 전제) | 허용 |
| editor | 허용 프로젝트 범위 읽기/쓰기 | 읽기/쓰기 | 초기 MVP 거부; 추후 위임 정책 필요 | 원가·비공개 보고서 기본 거부 |
| viewer | 프로젝트 내 허용 정보 읽기 | 읽기만 | 거부 | 기본 거부 |
| outsider | 접근 금지 | 금지 | 금지 | 금지 |
| AI worker | owner의 계약·승인된 소스/도구/업무만 | 별도 승인 없는 수정 금지 | 독립적 승인 주체 불가 | 허가된 run 산출물만 |

기존 댓글/알림/초대/휴지통 접근은 별도 `PERMISSIONS_POLICY.md`와 현재 구현 호환성 검사 후 적용. 역할 변경/탈퇴/계약 해지 시 새 실행·읽기 작업마다 서버가 재검증. 전면 UI 숨김은 보안 수단이 아니다.

## 3. 사람 업무 관리
- 업무 생성은 owner/editor; 상태 `todo/in_progress/in_review/blocked/done`, 상태 변경 actor와 시각을 기록한다.
- viewer는 쓰기 금지. 작업 삭제는 기본 soft-delete. 복원/완전 삭제 권한과 보존은 운영 정책 승인 전 실제 영구 삭제 구현 보류.
- `blocked`에는 사유·차단 시각·해제 이벤트를 남긴다. `done`은 실제 산출물/검수 기준 충족 시점에서 변경.
- AI 역할 배정 정보 자체는 실행 명령이 아니며, 명시적 동의·계획 승인·run 시작을 별도로 요구한다.

## 4. 서비스 이용 계약·동의
- 사용자가 AI 사용을 시작하기 전에 모델 제공사/도구·처리 목적·대상 문서/버전·전송 범위·계약 기간·취소 가능 조건·요금/상한·데이터 처리 내용을 이해할 수 있게 안내한다.
- 최초 계약은 owner만 승인하며 계약 `terms_version` / `manifest_digest` / 비용 상한과 동의시각·주체를 서버에서 고정한다.
- 계약 범위/처리 조건/상한/공급자 변경은 새 버전·재동의가 필요하다.
- 미동의·만료·철회·서버 검증 실패 시 **모델 호출/새 실행을 차단**한다.
- 계약과 계획 승인·실행 승인·보고서 수락은 서로 다른 사건으로 기록한다.

## 5. AI 실행·검수·수락
- 첫 전문 역할 `requirements_auditor_v1`: 선택된 같은 프로젝트 문서 2건 이상 읽기(R0), 서버가 신규 비공개 감사 보고서만 생성(R1). 기존 문서 덮어쓰기/발송/배포/결제는 불가.
- AI PM이 무과금 사람 계획 초안을 제안하는 경우 AI가 자동 생성했다고 표기하지 않는다. AI 모델 계획 생성은 별도 사전 비용 동의 후 실행.
- 실행 상태는 서버 `queued/running/validating/succeeded/failed/cancel_requested/cancelled/blocked_reconciliation`로 고정하고, 사용자에게는 별도 산출물 acceptance 상태를 결합해 표시.
- run succeeded는 기계적 처리 성공이지 **보고서가 정확하다거나 사람이 accepted했다는 뜻이 아니다**. 보고서 수락은 owner가 해당 버전/digest를 확인한 별도 기록.
- 승인 철회·계약 만료·프로젝트 접근권한 상실 뒤에는 새로운 문서 읽기/도구 호출을 금지. 취소 중 외부 제공자가 이미 수행한 작업은 별도 '정산 미확정'으로 표시.
- 모델 출력의 근거 인용·문서 hash를 검사하고, 검증 불가능/근거 부족 항목은 명시적 검토 필요로 표시.

## 6. 비용·요금·결제·환불
| 항목 | 초기 규칙 | 상용화 전 결정 |
|---|---|---|
| 예산 | 프로젝트/계약/PM 계획/run 별 승인 상한; 초과 실행 거부 | 원화 기준 기본 금액·통화·환율 |
| 공급자 원가 | 예약(reserved), 관측(observed), 미확인(pending), 정산(settled) 구분 | 공급자/호스트별 원가 실측 |
| 고객 청구 | 별도 청구·결제 원장 및 결제 승인 후에만 발생 | 단건·크레딧·구독 상품/가격 |
| 무료 체험 | 외부 모델 비용 미승인 상태에서는 mock/fixture만 무료 테스트 | 실제 무료 쿼터/유효기간/카드 요구 여부 |
| 실행 실패 | provider 비용이 실제 발생할 수 있어 실패=원가 0이 아님 | 고객 요금 환불·재실행 정책 |
| 중복 요청 | 동일 key+동일 payload에는 기존 결과 반환, 다른 payload는 409 | 클라이언트 키 재사용/만료 |
| 공급자 상태 불명 | 재호출/중복 청구 방지 위해 보류, 원가 0으로 확정 금지 | 고객 고지·수동 대사 SLA |
| 구독 취소/환불 | 현재 실결제 미도입, 고객에게 환불액 약속하지 않음 | 청약철회/관련 법규/결제사 조건 법적 검토 |

**절대 금지:** 사용자 계약 동의 전에 유료 모델 계획 생성, 사용자 예상 비용을 실제 청구액으로 오표기, 자체 비용 원장과 고객 청구 원장을 혼합, 불명확한 provider 결과를 무조건 실패/무료로 확정.

## 7. 개인정보·데이터 보존·삭제·이동
- 수집 최소화: 로그인 및 프로젝트 관리에 필요한 정보만. 모델 호출은 해당 업무에서 owner가 명시적으로 선택한 문서/최소 문맥만 전송.
- 고객/팀 데이터는 프로젝트 단위 격리. 공급자에게 보내기 전 데이터 처리 목적·국외 이전·학습 활용·보존 기간·삭제/처리 조건을 확인하고 필요한 동의/고지를 완료.
- 로그는 원문 전체/비밀번호/인증 토큰/API 키 저장 금지. 서비스 지원·감사 로그와 보고서 원문은 분리 저장하고 누가 언제 접근했는지 기록.
- 프로젝트 삭제·회원 탈퇴 시 사용자 화면의 삭제와 DB/백업·법정 보관 정보를 분리 안내. 이용자에게 실제로 확인되지 않은 '즉시 영구 삭제' 표현 금지.
- **미확정 필수 항목:** 원문/보고서/대화/업무/감사 이벤트/청구·정산 기록별 보존 기간, 백업 삭제 기한, 모델 공급자 학습·로그 처리, 데이터 내보내기 형식·제3자 제공 근거, 미성년자 정책, 운영자 지원 접근·긴급권한.
- 별도 B-04 로컬 초안 저장은 공유 기기 정보 노출 위험이 있어 사용자 고지·저장 만료·계정 변경·용량 부족/브라우저 종료 복구·다중 탭 충돌을 검증하기 전 완료 처리하지 않는다.

## 8. 장애·재시도·지원
- 저장 오류: 입력 중 내용 유지, 저장 실패 경고 및 복구 경로 제공. 무조건 '저장 완료' 표시 금지.
- AI 실행 503/타임아웃: 실행 ID는 유지, 안전 재조회. 공급자 결과 불명확하면 `blocked_reconciliation` 상태로 추가 호출 금지.
- 작업 취소: 새 도구 실행 차단, 이미 발생한 provider 비용 및 취소 불가능한 작업은 사용자에게 분리 고지.
- 지원 사건 기록: 프로젝트 ID, 요청 ID, 증상/오류 코드, 조치/시각, 데이터 접근 동의 및 접근 로그. 원문/민감 정보는 일반 지원 티켓에 복제 금지.
- 보안 사건: 신규 도구/모델 호출 차단(킬 스위치), 로그 보존, 영향 프로젝트 범위 분류 및 법적 통지 요건 확인. 실제 고객 통지 기한은 관할 법규 검토 후 확정.
- 고객이 보고서 내용 오류를 신고하면 기계 검증 결과와 의미적 품질을 구별해 검토하며, AI 산출물이 사실임을 보증하지 않는다.

## 9. 사용자 알림·상태 고지
- 계약 동의/해지, 승인 요청·결정, run 성공/실패/취소/정산 보류, 결과 수락·반려, 권한 변경은 권한 있는 사용자에게만 안내.
- 앱 내부 알림은 사용자 사건과 일치한 뒤 표시. 이메일·푸시 외부 발송은 해당 채널 운영/동의 정책 결정 뒤 도입.
- 비용 표시는 통화/단위/예상·예약·관측·정산·청구 여부를 함께 표기.

## 10. 법적·상용 운영 승인 체크

| 모델 제공사 이용 조건·국외 이전·학습/보존 확인 | 미완료 | 실제 사용자 원문 외부 전송 |

| main/운영 DB migration/배포 별도 승인 | 미완료 | 운영 변경 |

## 11. 미결정 레지스터와 완료 기준
**필수 승인 항목:** OP-01 첫 AI 역할 공개, OP-02 사용자 가격/과금, OP-03 모델/서비스 사업자와 데이터 처리, OP-04 문서/산출물/로그/백업 보존·삭제, OP-05 고객/팀 권한 위임 및 viewer 댓글, OP-06 지원/분쟁/환불 처리, OP-07 운영 DB 및 배포.

**설계 완료 정의:** 서비스 사용 시나리오별 책임/차단/실패 복구 규칙과 고객 안내 문구가 누락 없이 매핑되고, 미결정에는 담당·승인 게이트가 표시됨.
**제품 완료 정의:** 실제 SQL/RLS·API·E2E/장애/비용 검증 + 상용 정책 승인 + 제한 파일럿. 현재 이 문서만으로 제품 검증 완료가 아니다.

**관계:** 서비스 상품·가치·고객 여정은 `SERVICE_PLAN_V1_2026-10-20.md`, 구현 API/DB는 `../engineering/MVP_BUILD_READY_SPEC_2026-10-20.md`, 초기 권한은 `PERMISSIONS_POLICY.md`, 구체 비용/계약 근거는 `MVP_CONTRACT_APPROVAL_COST_POLICY_2026-10-19.md`. 최초 기획 PRD 및 기존 Phase 1 설계는 보존.
