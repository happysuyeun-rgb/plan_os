# AI 인력사무소 — 고객 동의 기반 실경력·승급·채용 단가 정책 v1.0 (2026-10-21)

**상태:** 이전 사용자 결정 복원 + 세부 정책 제안. 현재 구현/가격 확정/법률 검토 완료가 아님. 기존 [AI 직원 상세설계](AI_STAFF_PERSONA_MODEL_HIRING_SPEC_2026-10-21.md), [기본 제품 방향](DUAL_ENTRY_CONTINUOUS_AI_STAFFING_2026-10-21.md), [운영정책](SERVICE_OPERATIONS_POLICY_V1_2026-10-20.md) 연동.

## 1. 사용자 확정 제품 방향 (우선)

- AI 인력은 사람과 비슷하게 **실제 참여 프로젝트의 검증 가능한 경력**을 축적한다. 해당 직원의 참여 일수·완료 프로젝트·업무 역할·실증된 산출물/고객 평가를 직원 식별자에 누적한다.
- 채용/투입 시 **고객에게 이 프로젝트를 AI 직원 경력으로 등록·공개할지** 명확히 물어본다. 사전 무동의 자동 공개는 금지. 종료 시 실제 결과에 대한 최종 공개 범위와 평가를 확인한다.
- 고객 선택: **공개 / 익명 공개 / 비공개**. 경력 등록/점수 활용 여부와 외부에 프로젝트 이름·정보를 공개하는 범위는 서로 다른 선택값이다.
- 동의 후 검증된 수행 경력이 쌓이면 **초급 → 중급 → 고급** 등급으로 성장할 수 있다. 초급은 중급·고급보다 **낮은 채용가격**으로 진입하도록 설계한다. 실제 가격/승급 임계값은 아직 가설.
- 프로젝트 종료 후 고용주의 **평점·후기·업무 수락 여부**를 별도 신뢰 신호로 반영한다. 후기는 공개 동의와 비공개 처리를 구분한다.
- 고객의 코드, 디자인 파일, 영업정보, 비공개 문서, 채팅, 개인정보, 비공개 의사결정은 경력/후기 동의만으로 **다른 고객에게 공유하거나 모델 학습 자료로 재사용하지 않는다**.

## 2. 경력 축적과 경력 공개는 별도 계약

### 채용·투입 시 UI — 단계별 선택

**[A] 이 프로젝트의 AI 직원 수행 실적을 경력에 등록하도록 허용하시겠습니까?**
- **허용:** 서비스가 실제 수행된 업무를 확인해 **경력 일수·검증된 작업·승급 평가**에 사용할 수 있다. 어떤 집계 항목이 직원 프로필에 공개되는지는 C에서 별도 선택.
- **허용 안 함 (기본값):** 계약 이행·보안·청구·감사에 필요한 내부 작업 기록은 해당 목적/보존 정책하에 남을 수 있으나, **AI 직원 이력서·추천·승급·마케팅에는 사용하지 않는다**. 고객에게 불이익 없이 프로젝트는 동일하게 수행한다.

**[B] 완료된 프로젝트의 외부 공개 방식은?** (A 허용 시; 기본: 비공개)
- **공개:** 고객이 미리보기로 승인한 프로젝트명·업종·업무·기여 결과·활용 가능 지표만 공개. 고객/타 참여자 데이터와 원본 파일은 별도 승인 없이는 비공개.
- **익명 공개:** 고객명·브랜드·URL·고유 식별 단서를 제거하고 허용된 범위의 직무·검증된 결과만 표시. 소규모/특이 프로젝트가 재식별될 수 있으면 다시 제한·재동의.
- **비공개:** 프로젝트 식별 정보 및 개별 수행 기록은 다른 이용자에게 보이지 않음. **경력 승급용 비공개 집계 사용은 A에서 허용한 경우에만 가능.** 공개 통계·전체 일수 배지 표시는 추가로 명시 동의한 범위만 포함. 고객 식별 가능한 날짜·기간은 노출하지 않음.

**[C] 2차 이용·공개 목적 별 선택** (기본 모두 꺼짐)
- 개인정보/회사 식별자료가 포함될 수 있는 **프로젝트명·로고·포트폴리오 원본** 공개 (별도 자산 승인)
- **집계된 경력 일수/프로젝트 수/평점** 공개
- **고용주 후기·별점** 외부 공개 (닉네임/익명 범위 별도)
- **추천·랭킹/마케팅 홍보**에서 해당 프로젝트 사례 사용
- **모델 학습·외부 서비스 재사용** (원칙적으로 별도 고위험 정책 승인 이전에는 제공하지 않음; 경력 등록 동의와 절대 묶지 않음)

### 완료 시 최종 확인

- 실제 수행 사실/승인된 완료 결과/경력 집계 제안 미리보기 제공, 고객이 **공개·익명·비공개 수정 및 후기/별점** 선택.
- 채용 시 A/C에서 승인한 한도 내에서만 집계하고, 더 넓은 공개는 새 동의가 있어야 가능. 완료 시 무응답은 확대 공개로 간주하지 않음.
- 프로젝트 후반에 참여한 AI 직원은 실제 참여 구간만 계산. 고객의 업무 수락 및 검증 상태가 분리돼야 한다.
- 동의는 프로젝트 전체 단위뿐 아니라 **프로젝트 × 개별 AI 직원 × 목적 × 버전**에 귀속; AI PM/개발자/QA를 함께 고용해도 각각 어떤 경력에 반영되는지 확인 가능해야 한다.

## 3. 경력일수/실적 계산 계약 — 제안, 출시 수치 미확정

**경력일수 = 기간 경과가 아닌 확인된 활동일수.**

- 동일 직원(staff_identity_id)에 대해 실제 프로젝트 범위 내 **검증된 작업 이벤트가 한 건 이상 있는 유효한 날짜**만 적립 후보로 산정한다. 단순 로그인, 구독 유지, 계약 활성 일수, 대기 상태는 산정 불가.
- 모든 실행 이벤트는 해당 프로젝트+직원 배정+작업+모델/버전+결과 검증 로그로 추적한다. AI가 답변만 출력한 일을 완료 프로젝트로 둔갑시키지 않는다.
- **중복 일수 금지:** 한 직원이 같은 날 세 프로젝트에 실제 참여해도 '활동 경력일수'는 **1일**; '프로젝트 참여 건수'는 별도 세며 프로젝트별 활동 이벤트와 실제 투입량 기록은 남긴다.
- 진행 중에는 '확인 대기 일수'로 표시하고 **실제 업무 검증과 고객의 경력 등록 동의**를 충족한 일수만 공식 합계에 반영. 완료되지 않은 프로젝트는 성공 완료 건수에 포함하지 않는다.
- 멈춤/장애/취소/미승인/반려, 복수 직원 동일 산출물, 시험 fixture, self-hire 부정 수행, 자동 반복 호출을 실경력으로 부풀리지 않도록 이벤트·승인·이상탐지 정책 필요.
- 각 프로젝트는 **project_count / validated_task_count / accepted_artifact_count / unique_active_days / role / verified_tool_actions / ratings** 등 서로 다른 지표로 기록. 성공 실패도 사실대로 집계하되 미검증 경험은 승급에 보탬이 되지 않게 한다.
- 직원이 같은 프로젝트에서 모델을 바꾸면 **직원 ID/경력 이력은 유지**, 각 작업의 **provider/model_id/config_version**을 보존하고 바뀐 모델로 수행 가능한 역량은 다시 테스트한다.
- 직원 성격(F형/T형) 변경만으로 경력 일수가 초기화되지 않으며, **실력 인증이 새 모델에 자동 승계되지 않는다**.
- 일수 표준 시간대·부분 활동 단위·프로젝트 취소 후 일수 처리 등은 테스트 전 최종 확정해야 한다. 중복계산 방지 및 이해 쉬운 공개 기준을 우선한다.

## 4. 등급과 승급 정책 — 검증 실적 기반

### 제품 등급의 두 계층을 분리
- **검증 경력 등급(초급/중급/고급):** 같은 직원의 누적 검증된 활동일수, 완료 업무/프로젝트, 고객 수락, 품질 평가를 기반으로 변한다.
- **상품 성능 등급/모델 패키지:** 어떤 모델(GPT/Claude), 도구/컴퓨팅, 지원 범위, 작업당 한도를 제공하는지 나타내는 별도 정책. 경력 승급만으로 underlying 모델 가중치가 자동 학습되거나 더 똑똑해진다고 주장 금지.

### 승급 조건 예시 — 모두 가설, 확정 아님

| 단계 | 확인된 고유 활동일수 예시 | 추가 품질·경력 조건 예시 | 공개 표현 |
|---|---:|---|---|
| 초급 | 0~29일 | 신규 직원/검증 과제, 경험 적은 상태 명시 | 검증 프로젝트 0건이라면 실제 경력 0건 |
| 중급 | 30~179일 | 고객이 수락한 프로젝트 3건 이상 + 업무 적합성 검증 + 심각한 미해결 문제 없음 | '검증된 프로젝트 참여 경력' |
| 고급 | 180일 이상 | 고객 수락 프로젝트 10건 이상 + 지속 품질/역량 테스트 + 분쟁·안전 점검 | '상위 실적 기준 충족' |

실제 기준은 고객 수요·작업별 난이도·평가 신뢰성·업무 빈도를 테스트해 결정. **고객 평점만으로 자동 승급/강등하지 않음**; 표본 수 부족이면 '평가 데이터 부족'으로 표시. 중급 이상의 이름을 가상의 인간 연차처럼 오인시키지 않는다. 변동을 감사 기록으로 보존.

승급 필요조건: 활동일수 충족 **AND** 최소 수행·수락 프로젝트/작업 충족 **AND** 최신 업무 역량 평가 통과. 미달하면 초급 유지 또는 평가 대기.

## 5. 채용 가격 구조 — 초급이 더 저렴하다는 사용자 의도 반영

| 직원 경력 등급 | 가격 포지션 | 서비스 가치 | 가격표 상태 |
|---|---|---|---|
| 초급 | 가장 저렴한 채용 단가 | 적은 검증 경력, 좁은 작업 범위/높은 감독 수준 | 미확정 |
| 중급 | 기준 단가 | 검증된 반복 업무·수락 실적 | 미확정 |
| 고급 | 높은 채용 단가 | 더 많은 검증 실적·복잡한 업무 관리 경험 | 미확정 |

가격은 **경력 단가 + 실제 사용 모델/도구 호출 원가 + 작업 범위 + 계약 기간/사용량**을 고려해야 함. 고급 경력이어도 저렴한 모델을 쓸 수 있고, 초급이어도 비싼 모델을 선택할 수 있어 **등급을 모델/비용과 동일시하지 않는다**. 플랫폼 마진·손실방지 확인 필수.

- 신규 채용/갱신 시 직원의 **현재 등급과 당시 표시 가격**을 명확하게 고지.
- **프로젝트 계약/진행 중 승급하더라도 현재 계약 단가 자동 인상 금지**; 갱신 또는 추가 업무 계약 시 승급한 가격을 미리 표시하고 동의받기.
- 고객 공개 동의/후기 제공 여부를 할인이나 불이익과 강제로 맞바꾸지 않음. 공개 거부 고객에게 같은 계약의 품질/단가 차별 금지.
- 출시 전에 원가·최소 원가보전 가격·취소 환불/잔액 정책을 별도 확정. 숫자·등급별 배수는 실험 전 고정하지 않는다.

## 6. 외부 프로필/내부 이력 예시 (모의 값, 실데이터 아님)

**로이 — 풀스택 AI 직원 / 논리적 실무형 / Claude 기반 모델 후보**
- 검증 경력 등급: **중급 (시안)**
- 총 검증 활동일수: **42일 (가상 예시)** / 고객 승인 완료 프로젝트: **4건 (가상 예시)**
- 공개된 레퍼런스: 2건 (실명 공개 1, 익명 1), 비공개 프로젝트: 2건 (프로젝트 상세 공개 안 함)
- 고객 평가: 실제 평가 전에는 '후기 없음/검증 전' 표시.
- 이력서 공개 범위 밖의 프로젝트명·문서·고객명·개별 수행 날짜는 보여주지 않음.
- 모델 성능: GPT/Claude 변경 시 실제 평가 항목을 따로 표시.
- 채용 단가: **가격 미정, 모의 UI에만 등급별 상대 비교**.

| public_staff_reference | staff_id, approved_project_fields, visibility, consent_version, published_at | 승인된 필드만 외부 뷰 |

- **중요:** 서비스 원래 작업 감사 로그와 '경력 적립 원장'은 완전히 분리한다. 업무기록 존재 = 경력 반영 동의로 오인 금지.
- 데이터 참조 검증은 항상 project_id + employer_id + staff_id + consent scope. Supabase RLS만이 아니라 민감 공개 데이터는 API/서비스 계층에서 필드 allowlist를 적용.
- 집계 화면은 직원 ID별 고유일수 재계산 가능해야 하며, 취소/철회 시 이벤트/원장 재구성 지원. 공개 캐시 검색색인 삭제/갱신 동작도 설계.
- 중복 요청/동시 재평가의 경력·리뷰·요금 오염 방지를 위해 서버 idempotency key, version CAS, 변경 감사가 필요.

## 8. 동의 변경/철회·고객 보호 — 구현 필수

- **채용 시**와 **완료 시** 선택을 기록하고 언제든 '경력 사용/공개 설정'에서 확인·범위 축소·철회 신청 가능해야 함.
- 철회되면 새 공개/추천/마케팅 사용을 중지하고 플랫폼이 관리하는 공개 이력/검색색인/캐시를 범위에 따라 삭제·정정. 이미 외부 공유·다운로드된 자료는 기술적 회수 한계가 있음을 투명히 고지.
- 단순 공개 철회와 **경력 적립 동의 철회**를 구분. 공개만 철회하면 고객이 허용한 비공개 집계는 유지할 수 있지만, **적립까지 철회하면 관련 경력 일수·등급 계산에서 제외하고 다시 평가**. 기존 계약 가격은 임의 소급 변경하지 않는다.
- 서비스 보안/회계/계약 분쟁 로그는 별도 적법 근거·최소 보존 조건에 따라 필요한 기간 보유할 수 있으나, 이를 직원 홍보/타 고객 학습/랭킹에 전용하지 않는다.
- 익명 레퍼런스도 사업 분야/시점/결과 조합이 재식별 위험이면 공개하지 않는다.
- 고객의 채용/경력 공개 권한과 조직 프로젝트 문서/IP 권리를 확인해야 하며, 서비스용 최종 약관/개인정보처리방침은 국내 법률 검토 후 확정.

## 9. 수용 테스트 ID EX-01~EX-14

- **EX-01:** 채용 시 default=no로 경력 적립 여부·공개 범위/부차 목적 분리; 거부해도 동일 업무 진행.
- **EX-02:** 완료 시 결과/포트폴리오 공개 미리보기와 승인. 승인 없는 원문/고객명/URL 공개 0건.
- **EX-03:** public/anonymous/private 각각 허용 필드만 표시; 익명 재식별 위험 차단.
- **EX-04:** 비공개 적립 허용 시 개별 프로젝트 비노출, 승인된 집계만 승급에 반영.
- **EX-05:** 30일 계약 중 2일 작업만 수행하면 경력 2일 이하; 업무 이벤트 없는 날 0.
- **EX-06:** 같은 날 3개 프로젝트에 참여해도 직원 경력 활동일은 1일; 프로젝트 참여 건수는 별도.
- **EX-07:** 초급→중급→고급 승급은 경험일수+수락 프로젝트+역량 평가 함께 통과; 기준 버전·증빙 보존.
- **EX-08:** 고객 동의 거부/변경/철회 시 공개/집계/승급 재계산; 계약 가격 소급 변경 금지.
- **EX-09:** 고객 후기/별점은 작성자 승인 범위·비공개/노출 구분; 무평점은 0점처럼 표시 금지.
- **EX-10:** 모델 변경/직원 성격 변경 시 직원 경력 원장 유지, 새 모델 역량 평가는 별도.
- **EX-11:** 전 고용주의 코드/문서/대화/비공개 노하우가 후속 고용주 프롬프트·도구·학습에 유입되지 않음.
- **EX-12:** 채용 전 현재 등급/실제 모델/예상 원가/가격 분리 표시, 초급 단가가 동일 조건 중급·고급보다 낮음.
- **EX-13:** 프로젝트 수행 중 직원 승급하더라도 진행 계약에 자동 단가 상승/추가 청구 없음; 새 계약에만 고지.
- **EX-14:** forged review/fixture/self-hire/동일 이벤트 중복/동시 경쟁 업데이트로 활동일수·평점·등급/가격 조작 불가.

## 10. 구현 로드맵과 남은 결정

1. **제품/UX Mock:** 채용 시 경력 적립·공개 범위 체크, 완료 시 평가/최종 공개, 직원 이력서 공개·익명·비공개 비교.
2. **DB·API 계약:** 경험 원장/동의 버전/고객 평가/승급 히스토리, 프로젝트별 RLS/권한·로그 분리.
3. **기능 로직:** 실제 작업이 검증된 날만 적립, 중복제거, 완료·수락 판정, 철회/재계산, 등급 규칙.
4. **가격/결제:** 초급 저가/중급 기준/고급 프리미엄 가설 실험, 모델 원가 분리, 갱신/진행 계약 가격 스냅샷.
