## 1. 고객 가치를 분명히 만드는 10가지 권고안

| 결정 ID | 아직 남은 문제 | **권고하는 기본 결정(개발 설계용)** | 나중에 확인할 증거 |
|---|---|---|---|
| DEC-A | 무료/기본 AI 기획 vs 정식 PM 채용의 비용 이유가 불명확 | **기본 AI 기획 = 기존 인터뷰/기획 문서 생성·채팅 수정/프로젝트 단위 필요시 도움**, 정식 PM 채용 = **명시적 계약/선택 복수 프로젝트 통합 운영·직원 위임·근거 있는 지속 브리핑**. 단지 'F/T 말투'로 유료 구분 금지. 백그라운드 체크인·호출량은 실제 worker/원가 검증 전 약속 금지 | 기본 코칭 vs 지속 프로젝트 완결성이 유료 구매 이유인지 고객 테스트 |
| DEC-B | 같은 AI 모델로 초급/중급/고급을 만드는 것이 실제 가치 차이가 있는가 | **경력등급은 고객이 동의한 검증된 실제 활동일수·수락 결과+직무 평가**; 모델/도구 성능 패키지는 별도 상품. 시니어는 높은 성과 증빙/더 넓은 검증된 업무 범위/검토 수준으로 가치 입증. 허위 '10년 차 인간' 금지 | 등급별 결과의 실패율/재작업/수락률 비교 |
| DEC-C | 초급이 저렴하다는 정책을 수익으로 연결 | 같은 직무·모델·툴·계약 조건을 비교할 때 **초급 저가 < 중급 기준 < 고급 프리미엄**. UX Mock의 가격 비율 제안으로 초급 0.75×, 중급 1.00×, 고급 1.30× 같은 가설은 가능하나 **원가·마진 측정 전 실제 가격표/요금 승인 금지**. 현재 채용 snapshot 불변 | 원가/지원비·모델 지출·유료 전환 테스트 |
| DEC-D | 직원 경력일수 vs 다중 프로젝트/동일날 중복/철회 | 공개 경력은 **직원별 검증 활동일수**, 작업 원인은 프로젝트별 raw 이벤트. 집계 기준 하루=Asia/Seoul 00:00~23:59(기준 미리 고지), 고객 동의 없으면 적립 안 함; 취소/철회 시 남은 허용 이벤트로 재계산. 소급은 별도 동의 | 대량 병렬 작업/철회/재계산 시험·고객 이해 테스트 |
| DEC-E | 팀 프로젝트의 결과물 공개 권리자는 누구인가 | 기본 공개 권리 = **프로젝트 실제 owner/정당한 권리자**, 에디터나 AI 직원 스스로 동의 불가. 공동 소유/기업 고객의 권한 위임·IP/브랜드 승인 확인 전 원문/로고 게시 금지. 외부 포트폴리오/리뷰는 목적별 동의 | 개인정보·저작권·약관 법률 검토 |
| DEC-F | GPT와 Claude 직원 모델의 관계 | **직원 ID·업무 성격·실제 직무/경력은 공급자와 독립**. 직원별 성능평가된 기본 model_id 추천; 고객은 검증된 호환 모델 중 선택. 다른 제공자로 자동 fallback·재전송 없음. 원가/도구가 변하면 재고지·재동의 | 각 모델/직무별 golden task·툴/API·공급자 약관 비교 |
| DEC-G | AI 직원이 다른 고객 프로젝트를 수행한 '경험'을 얼마나 기억해야 하나 | **공유 직원의 연속성 = 공개 동의된 수행 메타데이터/평가만**. 전 고객의 비공개 기획·코드·채팅/프롬프트 기억을 다음 고객의 새 LLM 호출에 넣지 않는다. 능력 개선은 검증된 일반 툴/작업 템플릿 변경으로만 하며 고객 기밀 자료 전용 금지 | 테넌트 분리/데이터 추출 침투·공개 동의 검증 |
| DEC-H | 지속 PM의 자율 실행 범위와 책임 | 기본적으로 **PM의 자동 행동은 승인된 읽기/내부 초안·진행상태 브리핑까지**. 비용이 드는 모델 호출, 신규 직원 채용, 외부 발송/배포/파괴적 변경은 명시적 예산·권한·owner 승인을 요구. 자동 체크인은 scheduler/worker가 실제로 동작할 때만 표기 | 누적 원가·토큰·승인함 피로도·worker 장애 E2E |
| DEC-I | 직무 카탈로그를 처음부터 수십 개로 출시할지 | **처음 PM/풀스택/QA 3직무 × F/T 2성향** UX Mock로 채용/상호작용 이해 검증, 실제 유료 model 실행은 기존 기획서 검수 전문가 **한 직무**부터 검증. 실증 후 역할 확대, 기능 인증 배지 미검증은 표시 금지 | 실제 역할별 작업 10~20개 질적 평가 및 원가 |
| DEC-J | 직원이 동시에 여러 고객에 채용되면 연차·성능 신뢰가 가능한가 | 같은 캐릭터 `staff_id`는 여러 계약에서 공유하되 **고객마다 context/권한·요금·run 격리**, 합산 활동일은 직원별 하루 1회. '품절/면접 통과/근무 중' 같은 인위적 인간 희소성 연출 금지. 공급자 rate limit은 실제 큐 대기/제약으로 고지 | 동시 요청/공정성/큐 원가·고객 데이터 안전성 |

## 2. 지금 설계 기준으로 묶을 결정 vs 아직 실증이 필요한 결정

**즉시 채택 권고(실제 SQL/릴리스 승인 아님):**
- TF-01~46, 화면 N01~32, API STAFF-API-01~14와 데이터·권한 단일 정본 사용.
- 기존 AI 기획의 5종 문서/인터뷰·채팅/저장/버전·내보내기 보존; 고용 필수 아님.
- 직원 정체성/성격/직무·경력 검증/모델 패키지 분리. PM은 명시적 프로젝트 배정만, owner-only 최종 결정.
- 경력 적립 vs 외부 사례 공개·익명·비공개 vs 후기/원본·마케팅 목적 분리 및 기본 미허용.
- staff project contributions 원본 + 직원 고유 활동일 projection 분리·철회 재계산; 가격 snapshot 보호.
- 실제 업무 엔진과 고객용 AI 직원 카탈로그 Mock를 분리 출시.

**실제 근거/승인이 남은 부분:**
- 원가를 반영한 직원별 채용가격, 초급/중급/고급 승급 임계 일수/과업 난이도/평점 최소 샘플, 무료 이용 한도.
- 실제 OpenAI/Anthropic model_id/도구·성능·데이터 처리·국외 이전·고객 원문 보존/삭제 계약.
- 팀/조직의 프로젝트 공개 허용자, 고객 후기/포트폴리오 법적 권리, 철회/캐시·백업 삭제 이행 기한.
- 실제 정식 PM의 주기적 체크인 빈도/자동 작업 범위·예산, 신규 프로젝트 자동 포함 허용 여부(현재 기본 거부).
- 실제 `main` 테이블 agent_*·현재 작업 PR/SQL migration 순서와 데이터 모델 호환, QA PASS/배포.
