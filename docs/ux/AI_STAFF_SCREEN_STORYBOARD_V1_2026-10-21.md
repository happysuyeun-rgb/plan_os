## 1. 전역 내비게이션 / 서비스 유저 여정

```text
랜딩/로그인 → 새 프로젝트 또는 기존 프로젝트
              ↓
기존 AI 인터뷰 → 5종 기획 문서 생성 → AI 채팅 재생성/수동 수정/버전/내보내기
              ↓ (기존 프로젝트·문서 ID 유지)
프로젝트 진행 허브 ───────────── 계정 AI 인력사무소(/agents 기존 IA 후보)
 ├ 기본 AI 기획 계속                  ├ 직무·F/T·경력·모델·예산 필터
 ├ 필요한 AI 직원 단발 의뢰 ────────┤ 공개 직원 프로필/검증 증빙
 └ AI PM 정식 채용 ─────────────────┤ 계약형태·프로젝트 배정(명시선택)
                                     ├ 수행 계약/모델 전송·비용 동의
                                     ├ 프로젝트×직원 경력 적립·공개 별도 동의
                                     ↓
                        채용 직원/PM 담당 프로젝트 운영
                                     ↓
                        업무 초안/승인/실행/증빙/사용자 수락
                                     ↓
                       직원 경력 적립 후보·완료 평가·공개 최종확인
                                     ↓
                         직원 이력서/경력 등급/다음 계약 가격
                                     ↖ 공개/경력 사용 철회·PM 변경/해임
```

**UI 공유 컴포넌트:** `ProjectContextHeader`(프로젝트/문서 revision), `StaffBadge`(직무/실경력등급/검증 미완료), `PersonaPreview`, `ModelCapabilityDisclosure`, `ContractSummary`, `PermissionScope`, `ConsentPurposeRows`, `ApprovalAction`, `AuditActivity`, `SafeRetry`, `StaffAssignmentList`, `EvidenceLink`, `CostSnapshot`.

**공통 이벤트 데이터:** `actor_id, project_id, staff_id?, hire_id?, assignment_id?, source_revision_digest?, request_id, timestamp, terms_or_consent_version?` (실 컬럼명은 기술 계약 확정 시 일치시키기). UI에서 client가 제출하는 owner_id/worker validated result 값은 신뢰하지 않는다.

## 2. N01 기존 프로젝트 진행 허브 + C09/C10 AI 기획 KEEP

- **화면 목적:** 사용자가 기존 PlanOS에서 AI 인터뷰·기획서/채팅을 이어가면서 AI 직원 고용 필요성에 따라 바로 투입 가능.
- **정보 구조:** 프로젝트명/현재 접근권한 → `기획 문서`(PRD/기능명세·IA/화면목록·정책/프롬프트) → `현재 목표/단계` → 업무/담당/진척/승인 → `AI 직원`(없음·기본 제공·정식 채용) → 최근 산출물/저장상태.
- **1차 CTA:** `기존 AI 기획 계속`. **2차:** `AI 직원 찾기`, `기본 PM 도움받기`(실제 지원 여부 확정 전 Mock), `정식 PM 채용`.
- **상태:** 프로젝트 미생성/5종 생성 대기/문서 저장중·실패·conflict/PM 미채용/PM 일시중단/권한 403·삭제.
- **보안:** 기존 문서 주소·편집/복원 CAS 유지. AI 고용 버튼만으로 신규 모델 호출·과금·권한 부여 금지. editor는 기획/업무 수정 가능하나 owner 승인액션 숨김+서버 거부.
- **수용:** TF-01~06/25 및 TF-31, F-001~005, STAFF-01. 프로젝트/문서/채팅/버전이 고용 전후 동일 ID로 유지.

## 3. N16+N24 직원 탐색·비교 (신규 화면보다 기존 N16 확장 우선)

- **목적:** AI 모델명만이 아니라 맡길 일과 사용자 협업 방식에 적합한 직원 선택.
- **컴포넌트:** 검색창, 직무(PM/기획/풀스택/QA 등), F형 공감/T형 직설/분석/실행형, 경력등급(초/중/고/미검증), provider GPT/Claude, 필요한 도구, 예산·채용형태, 비교 패널.
- **카드:** 가상 아바타·이름, 직무, 업무 성향 한 문장, 검증된 경력일/수락 프로젝트/후기 표본(허용된 집계일 때만), 확인된 model_id·capability, 가격의 '미확정' 또는 동등 조건 상대단계; 공개 없는 수치는 공란.
- **액션:** `프로필 보기`, `비교하기`, `나의 프로젝트에 적합한지 살펴보기`.
- **오류:** 지원되지 않는 공급자/도구→추천 제외·명시, 빈 목록, 고급 등급이지만 해당 도구 검증 부재→거부.
- **수용:** TF-32, STAFF-02. 성향/직무/실경력/모델·패키지 서로 독립 필터, 허위 인간 재직 경력 금지.

## 4. N17+N25 직원 상세·성향 데모·공개 이력서

- **상단:** 표시명(가상 캐릭터 명시), 직무와 가능/불가 업무, 소통 성향 + 리딩 강도, 검증 경력등급/평가 기준, 최근 능력 테스트 일자.
- **탭:** `소개` / `역량·도구·모델` / `성향 미리보기` / `검증된 경력` / `후기` / `채용 조건`.
- **미리보기:** 동일 요구 '오늘 사업 아이디어를 실행하려면?'에 공감형/직설형 2~3턴 시연. 두 버전 모두 검증된 사실·위험 지적·다음 행동 포함; 직설형은 모욕하지 않고 공감형은 근거 없는 동의 금지.
- **이력:** 고객 동의 받은 공개/익명 프로젝트만 사례로 표기, 개별 미공개 프로젝트·산출물·소유자 식별 정보 접근 불가. 활동일수 집계 배지 자체가 비공개이면 공개 안 함.
- **액션:** `단발 업무 맡기기`, `프로젝트 전담`, PM일 때 `정식 PM 채용`, `기본 직원 교체`.
- **오류/권한:** 공개 데이터 권한/검증 부족이면 '검증 전/공개 허용 사례 없음'. 가격/평점 임의 0·가짜 후기 금지.
- **수용:** TF-32~33/41~43, EX-02~04, ST-02~04.

## 5. N19+N26 채용 형태·기본 직원 교체/추가

- **목적:** 기본 AI 기획 지속 vs 단발 업무 vs 프로젝트 전담 vs 다중 프로젝트 PM 정식 채용의 서비스 차이 이해.
- **선택 카드:** `기본 AI 기획 계속`(기존 AI 인터뷰/문서), `단발 전문 요청`(특정 일), `프로젝트 전담 직원`(선택 1개 프로젝트의 해당 직무), `정식 PM 채용`(명시선택 1개/복수 진행).
- **교체:** 현재 채용 직원·업무/계약·진행상태와 새로운 직원의 역할/성향/모델·예상 비용을 나란히 보여주고 '새 실행 중단/전문가 인수인계/기존 산출물 보존' 영향 확인.
- **CTA:** `배정 프로젝트 선택` 또는 `업무 범위 선택`; 금액이 미확정이면 실결제/실행 불가 Mock 고지.
- **권한:** owner만 실제 채용/해임; editor는 추천/계획 초안 작성·프로필 보기. 외부 공급자 모델 변경 시 데이터 전송 재동의.
- **수용:** TF-33/45/46, STAFF-03, 실행 계약과 실경력 공개 동의는 절대 묶지 않음.

## 6. N07+N27 프로젝트 배정·권한 범위 설정

- **목적:** 정식 PM에게 사용자 선택 A/B 프로젝트를 명시 배정하고 미선택 C와 미래 프로젝트는 기본 제외.
- **영역:** PM 고용 요약/현재 등급·모델/계약기간 → 접근 가능한 프로젝트 체크박스 + 검색 + 선택 결과(프로젝트별 권한: 읽기, 계획 초안, 업무 제안, 승인된 실행) → 비용·도구 범위 → `검토`.
- **정책:** owner가 **각 프로젝트에 대하여** 관리 권한 있는 경우에만 선택 가능. 팀 참여만 가능한 프로젝트의 채용·데이터 사용은 owner 별도 승인 경로 필요; 기본 거부.
- **CTA:** `프로젝트 선택 확인` → 계약/경력 동의. 미래 프로젝트 자동 포함 기본 비활성. 프로젝트별 예산 독립.
- **에러:** C를 무단 포함시키는 API 요청 403/404, 권한 상실 시 재조회·선택 해제, 같은 프로젝트 중복 배정 제거, 두 탭 수정 409 및 diff.
- **수용:** TF-34, STAFF-04/05, JWT/RLS/worker에서 동일 배정 검증.

## 7. N19/N20 실행 계약·모델·가격 확인 (고용 계약 검토)

- **필드:** staff_id, 단발/전담/PM, 선택 project_ids, 과업 범위, 도구/전송할 자료의 ID+revision/digest, 제공자/model_id, 승인 모드, 예상 사용량·예산 상한(통화/기간), 계약기간, 당시 직원 경력등급과 단가 스냅샷, 취소/환불 미확정 고지.
- **절차:** `초안`→`모델/자료 전송 범위 확인`→`예산·권한·기간 확인`→`채용 계약 승인`→`경력 사용 별도 선택`→`배정 완료`.
- **사전 조건:** 원가·공급자·개인정보 처리 미승인 상태는 실계약 승인/유료 모델 호출 CTA 비활성. Mock은 실제 active/청구로 표시하지 않음.
- **사람 권한:** owner만 계약·예산/유료 실행·최종 수락. editor의 계획 초안은 허용.
- **실패:** 만료된 견적, 이미 수정된 자료, 프로젝트 소유권 변경, 모델 능력 부재, 중복 승인/네트워크 유실→멱등 결과 재조회.
- **수용:** TF-10~12/35~36/46, S3 F-302/303, STAFF-06.

## 8. N28 직원×프로젝트 경력 적립·공개 동의 (별도 단계)

- **안내 문구:** “이 프로젝트의 실제 수행 기록을 해당 AI 직원의 경력/등급에 반영해도 될까요? 거부해도 동일하게 이용할 수 있습니다.”
- **1단계(필수 선택):** `경력 적립 허용하지 않음 [기본]` / `검증된 수행 실적에 한해 경력 적립 허용`. 처음 화면에서 어떤 프로젝트×직원인지 표시.
- **2단계(허용한 경우):** `개별 사례 비공개 [기본]` / `익명 공개` / `고객 승인 필드 실명 공개`; 익명 노출 시 재식별 위험 고지.
- **3단계(모두 독립 초기 OFF):** 집계 경력일수·참여프로젝트 수 배지 공개, 별점/후기 공개, 프로젝트 이름/로고 사용, 원본 포트폴리오, 서비스 홍보·랭킹. **모델 학습/외부 재사용은 여기서 일반 '경력 동의'로 허용되지 않으며 별도 정책 승인 전 OFF**.
- **CTA:** `선택 저장 후 계속` / `경력 이용 거부하고 계속`. 사용자 거절도 진행을 막지 않음.
- **실패:** 로그인 만료→입력 유지·재인증, 두 탭 상충→동의 버전 409/재검토, 조직 사업 자산 승인권 부재→비공개/미적립 유지.
- **원칙:** 업무를 수행하는 계약 동의와 직원의 공개 이력 목적 동의는 별개; 목적·프로젝트·직원·정책 버전과 선택·행위자 추적.
- **수용:** TF-35~36, EX-01~04, STAFF-08/11.

## 9. N29 정식 채용 PM 운영실 (단일·선택 복수 프로젝트)

- **헤더:** 담당 PM 프로필/리딩 성향, 고용기간·모델/가격·권한·상태, 배정된 프로젝트 수, `프로젝트 배정 변경`·`성향 조절`·`해임`.
- **왼쪽:** PM이 **실제 권한 있는 A/B만** 선택할 수 있는 목록·프로젝트별 상태/마지막 성공 체크 시각. C는 없음.
- **중앙:** 오늘 우선순위 1~3개·이번 주 마일스톤·막힌 점·담당 전문직원·수행 증거 링크·마지막 실행 시각/모델/상태.
- **오른쪽:** 승인함(계약/유료 계획/툴·실행/수락 별개 사건), 사용자에게 필요한 결정, 예상/예약/실제 비용, PM 진행 로그.
- **PM 말투 차이:** 하루 F형은 함께 해결·코칭하는 질문 우선, 태오 T형은 허점·우선순위 직설 진단; 동일한 근거/업무 상태를 기반으로 함.
- **업무:** `계획 제안`→사람 검토/승인→해당 전문 직원에게 위임 초안→승인된 도구만 실행→근거 검증→사람 최종 수락. 실제 지속 점검은 **백엔드 스케줄러/워커+budget/permission 재확인**이 있어야 함.
- **권한:** worker는 PM 소유자의 전체 프로젝트를 탐색하지 않는다. 허가된 특정 assignment/project만 접근. UI 통합 summary도 DB/서비스에서 해당 프로젝트 권한 검증한 데이터만 합침.
- **실패:** staff revoked, budget exhausted, source stale 409, 문서 edit 충돌, 백그라운드 워커 없음, provider outage/원가 정산 보류. 항상 마지막 성공/중단 이유를 표시.
- **수용:** TF-37~39, STAFF-05/06, ST-07~11.

## 10. N11/N12 결과·근거·승인함 (기존 실행 화면 확장)

- **구조:** 계약·문서 snapshot/최종 digest → 작업과 진행상태 → 검증 증거(테스트·인용·도구 호출) → 예산 예약/실제/미확정 → 사람이 최종 수락/수정요청/반려.
- **사건 분리:** `task.status`, `run.status`, `artifact.verification_status`, `artifact.acceptance_status`, `engagement.status`는 각각 다름.
- **승인 위험:** 새 모델 공급자 전송·실행/비용·외부쓰기·고객 원본 수정·최종 수락은 명시적으로 서로 구분.
- **실패 복구:** 승인 만료/자료 수정 stale→재승인, provider 미확인→안전 조회/중복 실행 차단, 동시 승인/해임→권한 재평가.
- **수용:** TF-13~24, TF-38~40.

## 11. N30 프로젝트·계약 종료 및 직원 평가

- **입력:** 프로젝트(여러 프로젝트 PM일 경우 **프로젝트별** 결과)·직원·실제 완료/수락 산출물, 검증된 고유 활동일 후보와 누락/미검증 설명, 비용 확정/미확정.
- **고객 선택:** 결과 수락/반려(별도 사건), 평점(작성 시만)/후기(선택), 직원 경력 반영 범위 재확인, 공개/익명/비공개 최종 미리보기.
- **종료 처리:** 다른 PM 배정 프로젝트가 남아 있으면 해당 건만 종료/경력 평가하고 직원 전체 채용이 반드시 종료되는 것은 아님.
- **리뷰:** 실제 수락/수행한 고객만 평가 가능. 평가 미응답은 0점/별점 조작 금지.
- **실패:** 허가되지 않은 파일/고객명 포함 시 게시 차단, 동의 변경 충돌 시 재검토, 미확인 work events는 경력 산정 보류.
- **수용:** TF-40~42, EX-01/02/09.

## 12. N31 직원 경력·승급·채용가격 (공개 프로필 뷰)

- **디자인:** 프로필 요약(가상 신분 고지), **실제 검증 활동일수/수락 프로젝트/평가 표본**(외부 공개 동의가 있는 통계만), 직무별 검증 역량, 초·중·고 등급·적용 기준 버전, 공급자 모델·도구 능력, 해당 등급의 신규 계약 단가(가격 미확정일 땐 표기 금지).
- **일수 집계:** 같은 직원이 A/B/C 세 프로젝트에서 하루 일해도 경력 '활동 일수' 1일, 프로젝트별 참여 기록은 별도. 고객별 비공개 프로젝트는 유추 불가.
- **승급:** 일수 + 실제 수락·품질 + 직무 평가가 모두 충족돼야 함. 등급은 **서비스 검증 경력**이고 사람의 실제 고용 연차나 모델 내부 학습 결과 아님.
- **계약:** 현재 진행 계약 단가 유지, 새 계약·갱신 전만 최신 등급/가격 고지.
- **상태:** 평가 표본 부족/검증 실패/동의 철회로 집계 재계산 중·등급 보류. 리뷰/가격 수치 조작 불가.
- **수용:** TF-41~43, EX-05~10/12/13.

## 13. N32 경력 공개·적립 동의 변경/철회 및 PM 해임

- **항목:** 현재 고용 직원·각 프로젝트별 적립 동의/공개 모드/배지/후기·포트폴리오/랭킹·마케팅 목적 권한과 consent_version.
- **두 개의 분리 CTA:** `외부 경력 공개만 철회` → 외부 프로필/색인 갱신 + 적립은 기존 허용 범위 유지; `경력 적립 자체 철회` → 해당 프로젝트 적격 work events 집계 제외·일수/등급 재평가. 후기 목적별 철회는 별도.
- **PM 변경/해임:** `담당 프로젝트 제거`(해당 project assignment 권한 회수) vs `직원 정식 채용 종료`(전 프로젝트 할당 비활성화) 구분. 진행 중 작업·견적/비용 미정·남은 계약 정보 미리보기.
- **행동 결과:** 요청 즉시 플랫폼 신규 공개/실행 차단; 비동기 공개 캐시/검색색인 갱신은 `진행 중/완료/실패` 정확히 알림. 삭제·백업 처리는 실제 법률 정책을 따름.
- **복구:** 재승인 없이 되살리는 전면 공개 금지; 버전 충돌 409, 철회 재요청은 멱등, 타인/직원 스스로의 철회 변경 거부.
- **수용:** TF-44~45, EX-08/11/14.

## 15. UI 상세 미결정 사항(실제 구현/상품 승인 전)

- 첫 번째 릴리스의 무료/기본 PM 명칭과 자동 체크인 약속 범위, 모델별 능력/패키지/가격, 실제 운영에서 누가 프로젝트 게시를 허락할 수 있는지, 모바일 공개 인력 정보 범위.
