## 1. 공통 설계 계약

### 1.1 공통 화면 상태
- `loading`: 스켈레톤·재시도 금지. `empty`: 최초 행동 CTA. `error`: 실패 원인과 재시도. `forbidden`: 접근 불가 안내, 민감 내용 노출 금지. `not-found`: 존재하지 않는 ID 안내.
- 쓰기 화면은 `pristine / dirty / saving / saved / conflict / error` 구분. 네트워크 오류로 입력 내용을 지우지 않음.
- AI 실행 상태는 `draft / planned / awaiting_approval / queued / running / verifying / awaiting_acceptance / accepted / blocked / failed / cancelled / rejected / needs_revision`. 서버 상태가 진실의 원천.
- 위험 작업 승인/거부/취소 버튼은 중복 제출 방지. 요청 중 비활성화, 멱등성 키 부여.
- 사용량은 `예상/예약/확정/환불` 구분, 화폐/단위/시각 명시. 모델 응답만으로 '완료' 표시 금지.
- 접근권한은 **서버 재검증**; 프런트 숨김은 보조. `owner/editor/viewer/outsider` 역할 세분화는 후속 권한 명세에서 확정.
- 각 주요 행위는 `actor_id, project_id, resource_id, timestamp, correlation_id` 감사 로그 연결(데이터 필드명은 제안).

### 1.2 공통 화면 구성
- 상단: 프로젝트명·현재 위치·접근 권한·예산 상태.
- 본문: 목표·데이터·상태·사용자 행동.
- 하단/보조: 최근 활동·검증 증빙·오류/복구·관련 문서.
- 모바일: 읽기/승인/실행 상태 확인 우선, 키보드 접근·포커스 이동·스크린리더 상태 안내.
- URL 딥링크는 접근 권한 없으면 데이터 없이 거부; 이전 화면으로 안전하게 이동.

## 2. MVP 상세 화면 9개

### N01 — 프로젝트 워크스페이스 허브
- **URL 후보:** `/workspace/:projectId` / **TF:** 04~06 / **진입:** 로그인+프로젝트 멤버십.
- **목적:** 사람 업무와 AI 팀을 한 프로젝트에 연결하는 시작점.
- **영역:** 프로젝트 브리프 요약, Solo/AI Team 전환, 진행 업무, 대기 승인, 예산 잔액, 최근 산출물.
- **액션:** 업무 보기, PM 계획 열기, AI 역할 찾기, 모드 전환. 모드 전환 자체는 실행/과금하지 않음.
- **검증:** 유효한 프로젝트, 권한, 활성 계약 유무, 기존 문서 링크 유효성.
- **예외:** 프로젝트 삭제/접근 철회, 계약 없음, 비용 초과, 빈 프로젝트.
- **수용:** 전환 전후 동일 프로젝트 ID·업무·문서·이력이 유지되고, 기존 `/projects/:projectId/:docType` 링크가 동작.

### N03 — 공통 업무 보드
- **URL 후보:** `/workspace/:projectId/tasks` / **TF:** 13~18.
- **영역:** 상태 컬럼, 담당(사람/AI), 우선순위, 기한, 승인 대기/실행 상태, 산출물 배지.
- **액션:** 업무 생성/편집/필터/담당 변경, 업무 상세 진입, 승인된 업무 위임.
- **필드:** title(필수), objective, assignee_type, assignee_id, status, acceptance_criteria, due_at(선택), artifact_refs.
- **검증:** 제목 공백 금지, 프로젝트 멤버/활성 역할만 담당 가능, 허용된 상태 전이만.
- **예외:** 동시 편집 충돌, 담당자 탈퇴, 계약 만료, 서버 저장 실패.
- **수용:** 사람/AI 업무가 하나의 목록에 보이며, AI 업무가 승인 없이 running으로 바뀌지 않음.

### N08 — AI PM 계획·검토
- **URL 후보:** `/workspace/:projectId/plan` / **TF:** 13~14.
- **영역:** 프로젝트 목표, 제약, PM 계획 버전, 업무·의존성, 성공 기준, 도구, 비용 예상.
- **액션:** 계획 초안 생성, 작업 순서/범위 수정, 재생성, 승인 요청, 기존 계획 비교.
- **검증:** 프로젝트 목표/역할/예산/권한, 순환 의존성, 실행 가능한 도구만 지정.
- **예외:** 모델 응답 불완전, 역할 부재, 비용 상한 초과, 이전 계획 변경 충돌.
- **수용:** 초안 생성만으로 서버 실행을 시작하지 않으며, 승인된 계획 버전이 추적됨.

### N11 — AI 실행 상세·증빙
- **URL 후보:** `/workspace/:projectId/runs/:runId` / **TF:** 17~18,20~24.
- **영역:** run ID, 계약/업무/계획 참조, 서버 상태, 도구별 로그, 산출물, 검증 결과, 예약/실제 비용.
- **액션:** 상태 새로고침, 실패 원인 보기, 재시도/취소 요청, 산출물 검토 화면으로 이동.
- **검증:** 해당 프로젝트 권한, 계약 범위, 서버 실행 상태, 중복 실행 여부.
- **예외:** 타임아웃, 부분 성공, 재시도 불가, 취소 불가 도구, 실행 로그 누락.
- **수용:** 브라우저 종료·재접속 후 상태/증빙 보존, 미검증 결과를 완료로 표시하지 않음.

### N12 — 프로젝트 승인함
- **URL 후보:** `/workspace/:projectId/approvals` / **TF:** 14,19,23.
- **영역:** 승인 대기·처리 완료, 대상 행위, 실행 주체, 영향/위험, 예상 비용, 만료 시각.
- **액션:** 승인 상세 열기, 승인/거부, 검토 의견, 관련 실행/산출물 이동.
- **검증:** 승인 권한, 요청 최신 버전, 만료/철회 여부, 금액/도구 변경 시 재승인.
- **예외:** 동시 승인, 이미 처리됨, 승인 만료, 권한 회수.
- **수용:** 승인되지 않은 배포/삭제/외부 발송은 실행되지 않으며, 승인·거부 근거가 남음.

### N16 — AI 역할 탐색
- **URL 후보:** `/agents` / **TF:** 07.
- **영역:** 역할/전문 업무, 도구, 검증 수준, 사용 가능 상태, 예상 비용 범위, 검색·필터.
- **액션:** 검색, 필터, 역할 상세, 프로젝트 선택.
- **검증:** 실제 제공 가능 역할만 표시, 비활성 역할 배치 금지, 비용 단위 명시.
- **예외:** 결과 없음, 공급자 장애, 역할 점검 중.
- **수용:** 인간 경력/가짜 후기/미검증 성공률을 표시하지 않음.

### N17 — AI 역할 상세
- **URL 후보:** `/agents/:agentId` / **TF:** 08~09.
- **영역:** 역할 설명, 실제 사용 가능 도구, 모델·데이터 처리 제약, 검증된 샘플/테스트, 계약 범위, 가격 가설.
- **액션:** 면담 시작, 프로젝트 선택, 계약 조건 설정.
- **검증:** 역할 활성 상태, 실제 검증 범위, 공개 가능한 샘플.
- **예외:** 지원하지 않는 업무, 역할 변경/중단, 가격 미확정.
- **수용:** AI 역할임을 명시하고 실제 성능 증빙과 마케팅 설명을 구분.

### N19 — AI 서비스 계약 조건
- **URL 후보:** `/agents/:agentId/contract` / **TF:** 10.
- **영역:** 프로젝트, 역할, 작업 범위, 허용 도구, 데이터 접근 범위, 예산 상한, 계약 만료, 취소/정산.
- **액션:** 조건 수정, 위험/비용 확인, 계약 검토 단계로 이동.
- **필드:** project_id, agent_id, scope, allowed_tools, data_access, budget_cap, expires_at, terms_version.
- **검증:** owner만 계약 요청, 역할/프로젝트 유효, 상한 양수, 계약 가능 도구만 선택.
- **예외:** 예산 미설정, 권한 부족, 도구/가격 변경, 중복 제출.
- **수용:** 조건을 읽고 명시적으로 동의하기 전 계약 활성화·AI 실행 없음.

### N20 — 계약 최종 확인
- **URL 후보:** `/contracts/:contractId/review` / **TF:** 11~12.
- **영역:** 조건 스냅샷, 변경 전후 비교, 취소/정산, 승인자, 계약 버전, 배치할 프로젝트.
- **액션:** 수락, 이전 단계, 거부, 활성 계약 후 킥오프.
- **검증:** owner 재확인, 계약 초안 최신성, 명시적 동의, 서버 멱등성.
- **예외:** 만료·변경된 조건, 다른 계정 동시 수락, 활성화 실패.
- **수용:** 계약 조건·수락자·시각·버전 감사 기록, 중복 클릭 시 계약 하나만 생성.

### TF-23 — 산출물 최종 수락/반려 UX 보완 제안 (DQ-05)
- **위치 후보:** N11 실행 상세의 검증 산출물 섹션에 **'결과 검토' 패널** 배치. 해당 작업이 N12 승인함에도 나타나되, 수락 의사결정은 동일 `artifact_id/version`의 하나의 서버 수락 API에 연결하여 중복 처리하지 않는다.
- **필수 표시:** 산출물명·버전, 생성·변경 시각, 작업 목표/수용 기준, 자동 검증 통과/실패·근거, 외부 부작용·남은 위험, 예약/확정 비용 구분.
- **행동:** `수락`, `수정 요청`, `반려`를 명시적 버튼으로 제공. 수정·반려 시 이유 입력, 수락 시 검증 결과·대상 버전 재확인. 권한 없는 viewer에게는 읽기 전용.
- **선행:** 서버가 검증 통과를 확인하고 `awaiting_acceptance` 상태일 때만 수락 가능. 버튼 클릭에서 최신 버전·계약/권한·중복 결정 확인.
- **예외:** 검증 실패(수락 불가), 이전 버전으로 변경(409 충돌), 승인 만료, 이미 수락/반려됨, 산출물 URL 권한 실패, 부분 실행·미정산 비용.
- **수용 테스트(미실행):** 검증 전 수락 차단 / owner 수락 1회만 기록 / viewer 거부 / 수정 요청 새 revision 추적 / 새로고침 후 상태 보존 / N12와 N11에서 동일 최종 상태.
- **미확정:** 수락 확인 모달과 검토 패널을 N11 안에 둘지 N13 상세로 통합할지는 와이어플로 검토 후 결정. 실제 화면·API 구현은 없음.

## 4. 핵심 상태 전이/화면 반응

| 이벤트 | 사전 상태 | 후속 상태 | UI 반응 | 금지 조건 |
|---|---|---|---|---|
| 모델 PM 계획 생성 | active contract + owner의 PM 비용·데이터 처리 동의 | generating → planned 또는 failed | 비용 상한·진행·재시도/실패 및 완료 버전 표시 | 계약/예산 동의 전 유료 모델 호출 및 승인 없이 전문 run 생성 |
| 계획 승인 | planned | awaiting_approval → queued(서버 검증 후) | 승인 이벤트 표시 | 만료·범위 변경 |
| 실행 시작 | queued | running | 진행 로그·취소 가능 여부 | 예산/도구/계약 위반 |
| 도구 결과 수신 | running | verifying | 검증 대기 표시 | 바로 accepted 처리 |
| 검증 통과 | verifying | awaiting_acceptance | 산출물·증빙·비용 표시 | 검증 없는 완료 |
| 사용자 수락 | awaiting_acceptance | accepted | 수락 기록·후속 작업 | viewer/외부인 승인 |
| 실패·취소 | queued/running/verifying | failed/blocked/cancelled | 원인·재시도 조건 | 중복 실행·중복 청구 |

**주의:** 상태 전이표는 제품 규칙 초안. 정확한 서버 enum과 취소 가능 시점은 아키텍처/DB 설계에서 결정한다.
